0.16.0 · 검증 결과와 배포 안내

말로 실행하기와 직접 녹화하기,
두 가지 흐름으로 정리했습니다.

실제 앱 조작, 저장 작업의 이어가기·새 실행과 자동 회귀 검사를 완료했습니다. 배포 파일과 공개 상태는 0.16.0 Release 안내를 확인하세요.

현재 확인한 범위

MuMu 첫 번째 줄의 실행 버튼을 한 번 누른 뒤 로딩과 녹색 실행 상태를 실제 화면으로 확인했습니다. Android 내부 준비 완료는 확인하지 않았습니다. 메모장은 입력 문구의 정확한 일치와 창 종료를 확인했습니다.

Chrome 시험 페이지의 입력·신청 상태 선택·조회 문구 일치와 종료, 계산기의 2 + 3 = 5와 종료, Store의 앱 항목 선택과 종료를 확인했습니다. 계산기의 중간 수식은 모델의 화면 확인을 거쳤고 최종 5는 UIA 값으로 확인했습니다. Store는 종료 응답이 처음에 불명확했으나 입력을 반복하지 않고 읽기 전용 재확인으로 창 종료를 확인했습니다. 설치·구매·로그인은 수행하지 않았습니다.

시험 앱에서는 수정 후 실제 동작 3개를 수동 보완·누락 경고 없이 5단계로 기록·저장했습니다. 그림 버튼 인식 문제를 고친 뒤 같은 실행을 이어가 5/5단계 완료를 확인했습니다. 조회 횟수는 재개 전후 그대로였고 그림 버튼 클릭만 1회 증가했습니다. 화면 확인 2개는 모델의 판단인 visual_assessed로 구분합니다.

이후 같은 저장 작업을 처음부터 새로 실행한 시험도 5/5단계를 완료했고 조회·그림 버튼 클릭은 각각 한 번씩만 증가했습니다. MuMu의 원래 녹화는 사용자가 편집창에서 한 단계의 대상을 다시 지정한 뒤 저장했습니다. 이후 중단 지점 이어가기와 처음부터 새로 실행하기를 각각 4/4단계 완료했습니다. 버튼 색상 차이는 모델이 현재 화면에서 같은 대상을 확인해 복구했고, 추가 수동 지정 없이 저장 원본을 유지했습니다. 이어가기에서 첫 클릭을 반복하지 않았습니다. 각 실행의 화면 확인 2개는 모델 판단인 visual_assessed입니다. 최신 캡처 변경은 자동 검사·시험 앱에서 확인했으며 MuMu의 원래 녹화를 모두 다시 수행한 것은 아닙니다.

최신 전체 검사는 1,327개 실행 중 1,325개 통과·2개 조건부 제외, 실패 0개이며 69.477초였습니다. 별도 독립 검사 191개도 25.947초에 모두 통과했습니다. 실제 화면 검증과 자동 검사 결과는 각각의 확인 범위로 구분합니다.

현재 검증 상태에 통과한 시나리오와 한계를 기록합니다. 아래 항목은 0.16.0의 구현 변경이며 모든 앱의 모든 기능을 검증했다는 뜻은 아닙니다.

사용자가 기억할 시작점

하고 싶은 일이렇게 요청하세요
AI가 화면을 읽고 실행“계산기를 열고 12 + 30을 계산한 뒤 확인해줘.”
직접 보여주고 반복 실행“이 프로그램에서 작업을 녹화할 수 있게 프로세스 편집창을 열어줘.”
저장한 작업의 입력값 변경“저장한 조회 작업을 오늘은 검색어 N으로 실행해줘.”

요소를 직접 고르거나, 이미지를 지정하거나, 녹화를 수정하는 작업은 모두 프로세스 편집창에서 합니다.

이번에 바뀐 내용

  • 기본 공개 도구를 12개로 정리했습니다. 프로그램 연결과 작업 세션 준비를 함께 처리합니다.
  • 현재 창과 관찰 결과에 연결된 요소 또는 이미지로 동작합니다. 동일한 버튼이 반복되면 행 이름 같은 구별 영역을 함께 사용합니다.
  • 이미지 이해가 가능한 모델은 전달된 화면으로 다음 동작과 실행 결과를 판단할 수 있습니다. MCP 자체는 외부 모델 API를 호출하지 않습니다.
  • 프로세스 편집창에서 단계를 수정하고 시험 실행할 수 있습니다. 수정한 작업은 새 버전으로 저장하고, 진행 중이던 실행은 시작 당시 버전과 입력값을 유지합니다.
  • 문자·숫자·날짜·선택값·목록 입력과 유한 목록 반복을 지원합니다. 스킬로 내보내면 저장된 작업과 버전을 호출하는 안내가 만들어집니다.
  • 메모장·계산기·Microsoft Store·Chrome의 설치 경로를 찾아 등록합니다. 기본 앱 업데이트로 경로가 달라지면 명시적인 재등록으로 갱신할 수 있습니다.
  • 입력 후 창이 닫혀도 입력 전달 기록을 보존하고 현재 상태를 다시 확인합니다. 성공 여부가 불명확한 입력은 자동 반복하지 않습니다.
  • 직접 대상을 수정하면 관련 단계의 대상 지정 경고를 정리합니다. 누락·입력값 미확인 같은 별개의 경고는 유지하고, 저장 버튼에서 실제 남은 검토 사항을 안내합니다.
  • 버튼 색상·상태가 달라 저장 이미지를 찾지 못한 경우, 이미지 전달을 허용한 모델이 저장 대상과 현재 화면을 비교하여 이번 실행에서만 같은 대상을 다시 지정할 수 있습니다. 입력 미전달이 확인된 단계에 한 번만 적용하며 저장한 작업과 인식 기준을 자동 변경하지 않습니다. 앞선 값·상태 조건을 다시 읽으며, 같은 창에서 모델이 확인한 결과는 화면 전체가 같을 때만 재사용합니다. 시계·애니메이션이 바뀌면 다시 확인이 필요할 수 있고, 이전 모델 확인이 다른 창에서 이루어졌다면 자동 이어가기를 멈춥니다.
  • 녹화 전에 캡처가 거절되면 실패 이유를 보여주고 시작을 멈춥니다. 기록을 마친 뒤 이미지가 없다는 사실을 뒤늦게 알리는 흐름을 보완했습니다.

성공 판단을 분명히 합니다

클릭 전달은 작업 성공을 뜻하지 않습니다. 읽은 값으로 확인한 결과, 모델이 화면을 보고 판단한 결과, 사람이 확인한 결과를 구분합니다. 저장·종료 대화상자가 남으면 앱 종료를 완료로 표시하지 않습니다.

프로그램마다 제공하는 요소 정보와 입력 지원 범위가 다릅니다. 모든 앱·모든 화면을 검증한 것은 아닙니다. 녹화 중에는 실제 앱에 동작이 적용됩니다. 구형 작업의 사람 확인 단계를 모델 판단으로 자동 변경하지 않습니다.
