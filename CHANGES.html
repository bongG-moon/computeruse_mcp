COMPUTER USE MCP 0.19.4

메뉴 의미 확인과 녹화 종료 처리

메뉴가 열린 근거를 보존하고, 같은 실행 재개에서 입력을 반복하지 않습니다.

0.19.4는 현재 UIA/MSAA 메뉴 이름과 계층으로 부모 펼침과 자식 명령을 구분합니다. 의미 관찰이 확인된 부모에는 녹화 당시 파란 강조 이미지를 필수로 요구하지 않습니다. 하위 메뉴만 열고 녹화를 끝낸 경우 기존 기록을 유지하고 해당 구간을 보완 대상으로 남깁니다. 기존 녹화와 revision, 명시적 사람 확인 및 로컬 정책을 유지합니다. 검증 범위와 GitHub Release를 확인하세요.

0.19.4 메뉴 의미 확인과 녹화 종료 처리

  • 현재 UIA/MSAA의 실제 메뉴 이름, 부모 경로, 표시 및 활성 상태를 확인한 뒤 부모를 펼치고 자식을 새로 찾습니다. 내부 필드명을 AutomationId로 추정하지 않습니다.
  • 하위 메뉴를 열고 항목 선택 없이 녹화를 끝내거나 메뉴를 취소해도 가져오기가 중단되지 않습니다. 앞선 기록과 원본을 유지하고 선택 근거가 빠진 구간만 보완 대상으로 남깁니다.
  • 기존 부모 메뉴 또는 연결된 자동 이미지 확인에서 ‘이 단계만 다시 지정’을 사용하면 확인과 동작을 함께 갱신합니다. 새 revision으로 저장하며 진행 중 실행은 원래 스냅샷을 유지합니다.
  • 이미지 전용 대상의 점수와 모호성 기준은 유지합니다. 글자 누락, 색상 변화, 전체 이미지와 클릭 행의 비교 결과는 로컬 결과창에서 구분합니다.

메뉴 명령 전달과 Excel 저장 완료는 별도입니다. 파일 생성 또는 허용된 결과 창의 완료 조건을 따로 확인해야 합니다. 전달이 불명확한 입력은 자동 반복하지 않습니다.

실제 사내 앱, 화면의 물리 클릭 성공 및 100/125/150% DPI 행렬은 미검증입니다. 시험 Provider와 회귀 검사 범위를 확인하세요.

0.19.3의 하위 메뉴 펼치기

  • 하위 메뉴가 실제로 나타난 호버를 하위 메뉴 펼치기(expand_menu) 단계로 보존합니다. 부모 대상과 자식 등장 조건을 함께 저장하며, 임의 마우스 이동이나 증거가 없는 펼침을 자동 입력으로 만들지 않습니다.
  • 별도 팝업 창과 같은 창 안의 UIA 논리 자식을 구분합니다. 이미 열린 자식은 입력 없이 다시 확인하고, 같은 실행을 재개할 때 이미 보냈거나 전달이 불명확한 입력을 반복하지 않습니다.
  • 메뉴 경로, 중단 위치와 입력 전달 상태를 로컬 결과창에서 확인할 수 있습니다. 기본 data_policy=local의 채팅 응답 허용 범위는 늘리지 않습니다.

누락된 호버가 있는 기존 녹화는 해당 메뉴 구간만 다시 녹화해 교체하고 새 revision으로 저장하세요. 원본 기록과 명시적 사람 확인은 자동 변경하지 않습니다. 실제 UIA 계층을 확인하지 못한 MSAA 전용 논리 메뉴는 자동 실행 단계로 만들지 않습니다.

메뉴 닫힘이나 명령 전달은 Excel 저장 완료가 아닙니다. 출력 파일 검증 또는 허용된 Excel 창의 결과 확인을 별도로 지정해야 합니다.

단위 검사와 합성 통합, offscreen 네이티브 및 로컬 진단 UI를 확인했습니다. 합성 시험의 XLSX는 시험 앱이 작성했습니다. 실제 사내 SmartMMDM 실행, 100/125/150% DPI 화면과 운영 Export 및 Excel 생성은 검증하지 않았으며 실제 업무 속도 보장도 아닙니다. 검사 수와 세부 범위를 확인하세요.

이전 0.19.2의 SmartFX 및 FXMenuAgent 개선

  • 승인된 실행파일과 실제 관찰 메타데이터로 호스팅 화면과 독립 업무 창의 처리 경로를 구분합니다. 별도 앱을 설치하거나 엔진을 고를 필요는 없습니다.
  • 드롭다운의 owner/parent 경로와 재표시를 확인하고, 실제 자식 컨트롤을 새 팝업으로 오인하지 않도록 보완했습니다. 유일한 현재 대상과 지원 동작이 확인되는 메뉴 및 목록 클릭은 요소 단계로 보존합니다.
  • 읽기 전용 접근성 진단에서 Provider, Driver 및 MCP의 누락 지점을 구분합니다. 이 진단을 모든 재생 단계마다 수행하지 않습니다.

기존 녹화, 이미지, revision과 명시적 사람 확인은 유지합니다. 입력 전달이 불명확하면 같은 클릭을 자동 반복하지 않습니다.

소스 회귀 342개와 실제 offscreen WinForms HWND 조건 12개를 확인했습니다. 운영 사내 앱의 전체 재생과 Excel 생성 성공을 증명한 결과는 아닙니다. 독립 업무 창 전환의 자동 녹화, 가상 표 셀의 Realize/ScrollItem 및 임의 PropertyGrid 편집은 남은 범위입니다.

관찰 메타데이터 정리 비용을 줄였으며 추가 전체 트리 진단이나 모델 호출은 없습니다. 이 측정은 실제 업무 전체 실행속도 보장이 아닙니다. 업무 창 안내, 접근성 진단, 검증 범위를 확인하세요.

이전 0.19.1: 로컬 모드의 설치 진단

0.19.0은 로컬 상태 응답에서 도구 구성과 도우미 진단 정보를 함께 제외했습니다. 이 때문에 실제 기본 도구 12개가 있어도 이전 구성의 도구가 없다고 판단해 설치 apply가 실패할 수 있었습니다.

0.19.1은 허용된 도구 구성, 고정된 도우미 파일명, 엄격한 존재 여부, 버전만 전달합니다. 업무 화면·입력값·내부 경로·상세 Driver 오류는 계속 로컬에 남습니다. 필요한 진단 정보가 없으면 정상 연결로 처리하지 않습니다.

닫힌 녹화 팝업과 시험 실행

팝업을 포함한 작업을 저장한 직후 시험 실행하면, 녹화 때의 닫힌 팝업 창 번호를 시작 대상으로 넘겨 Window no longer exists로 중지하는 문제가 있었습니다.

이제 실제로 필요한 기본 업무 창만 먼저 연결합니다. 동적 팝업은 작업의 wait_for_window 단계에서 현재 창을 다시 찾습니다. 기본 창 자체가 닫혔으면 입력 전에 중지하고 다시 연결하도록 안내합니다. 저장된 녹화·이미지·revision·실행 기록을 고치거나 사람 확인을 자동 승인하지 않습니다.

업데이트 방법

새 ZIP 전체를 별도 폴더에 풀고 기존 설정과 저장 작업을 유지해 연결을 갱신한 뒤 MCP 연결을 다시 시작하세요. data_policy=local을 유지합니다. Python 소스와 새 네이티브 도우미가 함께 필요하므로 ZIP 전체로 갱신하세요. 누락된 호버가 있는 기존 녹화는 해당 메뉴 구간만 다시 녹화해 보완합니다.

단계·입력값·스킬 보기, 같은 실행 재개, 로컬 스킬 내보내기는 그대로 사용합니다. 명시적으로 설정한 connected의 기존 동작도 유지합니다.

과거 기록: 0.19.1 검증 범위

최종 0.19.1 통합 검사 292개 중 291개 통과, 1개 제외였습니다. 설치·편집·창 연결과 패키징·배포 도구를 함께 확인했습니다.

설치 진단 관련 검사 76개가 통과했습니다. 실제 MCP stdio 연결로 기존 0.19.0의 로컬 진단 실패와 수정본의 통과를 비교했고, 격리된 export-only 설치의 prepare → apply를 확인했습니다.

시험 실행 관련 검사 192개 중 191개가 통과하고 1개가 제외됐습니다. 실제 숨김 Win32 창의 생성·종료를 포함하지만 팝업 탐색과 입력은 시험 대역을 사용했습니다. 운영 PC 업무 앱 재생이나 실제 UIA 업무 입력은 이번에 새로 수행하지 않았습니다.

0.19.0의 실제 시험 앱 두 단계 재생·XLSX 확인은 과거 검증 기록입니다. 새 검증과 과거 결과를 구분해 확인하세요.
