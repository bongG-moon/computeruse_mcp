확인한 결과와 남은 검증

메뉴 개선의 단위 및 합성 시험, offscreen 시험과 과거 실제 화면 검증을 구분합니다.

0.19.3은 실제 하위 메뉴를 연 호버를 별도 단계로 보존하고, 열린 자식 메뉴를 다시 관찰하는 재생 경로와 로컬 진단을 포함합니다. 기존 녹화, revision과 데이터 정책을 유지합니다. 검증 범위와 실제 게시 상태 및 배포 파일은 GitHub Release에서 확인하세요.

0.19.3 하위 메뉴 녹화와 재생 검증

2026-10-29의 메뉴 통합 결과를 기록합니다. 단위 검사와 합성 통합 시험, offscreen HWND 시험을 구분하며 아래 검사 수는 범위가 겹치므로 합산하지 않습니다.

로컬 진단 UI 시험7개 통과. 제한된 로컬 요약과 읽기 전용 결과 UI, 공개 MCP 응답의 메뉴 상세 제외.

VisualTools.cs와 ProcessEditor.cs 시험용 도우미를 컴파일하고 Python import를 확인했습니다. 이는 소스 시험 기록이며 최종 Release ZIP의 런타임, stdio 연결 및 원격 자산 체크섬 검증은 배포 절차로 별도 확인합니다.

확인한 동작

  • 실제로 자식이 나타난 호버를 부모 대상과 자식 등장 조건이 있는 expand_menu로 가져옵니다. 별도 팝업과 같은 창 안의 UIA 논리 자식을 구분합니다.
  • 현재 자식을 먼저 확인하고, 같은 실행 재개에서 전달했거나 전달이 불명확한 펼침 및 명령 입력을 반복하지 않습니다. 자식이 없거나 여러 개이거나 바뀐 경우는 성공으로 처리하지 않습니다.
  • 합성 통합은 실제 저장 및 revision 읽기와 재생 엔진을 사용합니다. 재시작을 흉내 낸 새 PID 및 HWND, 메뉴 순서 변화에서도 저장된 메뉴 대상과 별도 결과 조건을 확인합니다. OS 입력, 이미지 일치 및 화면 판정은 시험 대역입니다.
  • 명령 전달이 불명확한 동일 실행 재개에서 Export 입력을 반복하지 않습니다. 메뉴 닫힘과 상태 문구가 있어도 출력 파일이 없으면 파일 검증은 실패합니다.
  • 메뉴 경로, 중단 위치와 입력 전달 상태는 로컬 결과창에만 추가합니다. data_policy=local의 공개 응답 허용 목록과 관리자가 명시한 connected 동작은 유지합니다.

합성 시험의 XLSX는 시험 앱이 작성한 파일입니다. 실제 Excel 또는 운영 Export로 생성한 파일이 아닙니다. 메뉴 확인, 명령 전달, 출력 파일 및 Excel 결과 확인은 서로 다른 검증이며 합성 반복 시험의 시간은 실제 운영 성능 증거로 사용하지 않습니다.

남은 범위

  • 사내 SmartMMDM 실행과 실제 100/125/150% DPI 화면 행렬은 검사하지 않았습니다.
  • MSAA만 제공하고 실제 UIA 계층이 확인되지 않는 논리 메뉴는 실행 메뉴로 승격하지 않습니다.
  • 펼침 근거가 빠진 기존 녹화는 필요한 구간을 직접 보완해야 합니다. 기존 녹화와 revision은 자동 변환하지 않으며 명시적 사람 확인도 유지합니다.

재현 소스는 test_menu_expansion.py, test_recorded_menu_expansion.py, test_menu_hover_guard.py, test_menu_workflow_integration.py, tools/test_menu_recording_native.py, tools/test_local_menu_diagnostics.py와 fixtures/MenuExpansionRecorderTests.cs에 포함합니다. 실제 업무 캡처와 원본 녹화는 공개 소스에 넣지 않습니다.

과거 기록 · 0.19.0 실제 화면 시험

아래는 2026-10-25에 수행한 0.19.0 검증이며, 0.19.2에서 새로 재생한 결과가 아닙니다. 당시 영향 경로 검사는 381개 중 380개 통과·하드링크 권한 제한으로 1개 제외, 배율·미리보기 추가 검사 9개 통과였습니다.

  • 외부 접속 없는 Windows 시험 앱에서 실제 입력 hook을 사용해 두 단계(값 입력·체크 상태 변경)를 녹화했습니다.
  • 보이는 편집창에서 입력 단계를 실행 변수에 연결하고 revision 1로 저장했습니다.

시험 앱의 완전 종료를 확인하고 새 프로세스로 다시 시작한 뒤, 저장 작업을 로컬 입력폼의 다른 값으로 재생했습니다. 두 단계 모두 verified였고, 새 XLSX의 실제 셀에서 변경한 입력값과 Family 값을 확인했습니다. 해당 실행의 내보내기는 1회였습니다. Family 드롭다운을 새로 녹화·선택한 시험이 아니라 값 입력과 체크 상태 변경 두 단계의 검증입니다.

실제 Driver를 사용한 이 두 단계 재생의 active 시간은 12,320.35ms(동작 12,288.6ms, 창 연결 29.81ms)였습니다. 사용자 입력 대기는 제외했으며 기존 버전과 통제한 실제 앱 속도 비교는 아닙니다. 운영 업무 10초 완료를 보장하지 않습니다.

기존 재생 검증과 구분

이 절은 이전 안내의 검증 링크를 유지합니다. ClickOnce 관련 과거 시험은 프로그램 연결 안내의 범위를 참고하며, 이번 로컬 작성 경로의 시험과 구분합니다.

이전 0.18.8 및 이후 소스 검증에서는 중첩 팝업의 기존 22단계 작업을 재사용해 N·Hybrid 선택→조회→Export 메뉴→Active sheet와 XLSX 데이터 5행을 확인한 기록이 있습니다. 그 결과는 0.19.2의 실제 운영 앱 재생 검증을 대신하지 않습니다.

운영 SmartFX, 모든 앱·테마·DPI·다중 모니터의 동작은 별도로 확인해야 합니다. 모델 화면 판정만 통과한 경우와 실제 파일 생성·내용까지 확인한 경우를 구분합니다.

외부 전송에 대한 확인 범위

새 작성 기능에는 외부 모델 API·원격 OCR·업로드 경로가 없습니다. 로컬 정책의 공개 MCP 응답은 허용한 상태·식별자·개수와 제한된 제품 진단 정보만 반환합니다. 0.19.1에서 허용한 진단 정보는 도구 구성·고정 도우미 파일명·존재 여부·버전이며 업무 내용·내부 경로·상세 Driver 오류는 제외합니다. 스킬은 업무 값·이미지·내부 경로 없이 고정된 작업 버전을 호출합니다.

사용자가 다른 도구로 파일을 읽거나 채팅에 직접 입력한 내용, 업무 앱 자체의 네트워크 통신은 이 정책의 제어 범위 밖입니다. 회사 밖 통신 전체의 차단을 검증한 결과는 아닙니다.

오류가 나면 전달할 내용

제품 버전, 중단한 단계 번호, 오류 코드, 입력 전송 여부, 같은 실행 재개 여부를 알려주세요. 로컬 상세 오류에 업무 정보가 있다면 반출 정책에 맞게 가린 요약만 전달합니다. 원본 녹화·이미지·비밀번호·내부 주소를 무조건 채팅에 올리지 않습니다.
