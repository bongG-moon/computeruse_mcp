0.11.1 — 선택 창 표시·진단 보완

UIA 직접 선택 기능은 지원됩니다. 선택 창의 최소화·화면 밖·다른 가상 데스크톱 상태를 표시 완료로 오인하지 않도록 보완하고, 시작 중 일시적인 비표시는 제한 시간 안에서 기다립니다. 같은 실행의 현재 창 핸들로 준비 정보를 갱신하되 실제 표시 확인 없는 선택 결과는 저장하지 않습니다.

최소화·화면 밖·가상 데스크톱·일시 비표시·실행 권한 오류 조건은 Win32 및 프로세스 응답을 모의한 회귀 검사입니다. GUI 검증은 별도 시험 창에 자동 입력한 결과이며 실제 사용자의 운영 프로그램 성공이나 다양한 화면 환경을 검증한 것은 아닙니다. 보고된 운영 PC의 버전과 원본 오류 결과는 아직 받지 못해 그 PC의 원인은 확정하지 않았습니다. 새로 추가한 모든 프로그램의 UIA 지원을 보장하지 않습니다.

UIA에 요소 정보가 없는 실제 오류에만 프로세스의 이미지 선택 방법을 안내합니다. 취소·권한 오류·대상 불일치에는 이미지 방식으로 우회하지 않습니다. computer_elements 목록 조회와 computer_save_task는 직접 선택의 대체 기능이 아닙니다.

0.10.0 — 프로세스 작성·대기·화면 확인

새 네이티브 편집 창에서 요소·동작·입력값·완료 조건을 지정하고 순서대로 저장합니다. 요소 대기와 고정 대기를 지원하며, 화면 이미지 확인 단계는 일시정지한 뒤 명시적인 확인으로 이어갑니다. 이미지와 창/요소 임시 번호는 작업에 저장하지 않습니다. 직접 작성한 입력값은 저장됩니다.

요소 검증은 Driver의 frame 위치 형식을 처리하고, 자동화 ID가 누락된 경우 정확한 이름·종류·위치를 모두 비교합니다. 실제 로컬 자체 렌더링 앱에서는 네이티브 UIA에 버튼이 없고 Driver에도 조작 요소가 0개임을 읽기 전용으로 확인했습니다. 이 경우 UIA 학습을 지원한다고 표시하지 않으며 그림 버튼 학습은 이번 버전에 포함되지 않았습니다.

0.9.0 — 선택 창에서 확인하고 가르치세요

채팅에서 “이 화면의 신청 상태를 직접 가르쳐줄게. 요소 학습을 시작해줘.”라고 요청합니다. MCP가 선택 창이 실제로 표시됐는지 확인한 뒤 기다립니다. 창이 보이지 않는데 F8을 누르라는 안내를 반복하지 않습니다.

  1. 선택 창에서 3초 후 위치 선택을 누른 뒤 원하는 입력칸·선택 상자·버튼 위로 마우스를 옮깁니다. 또는 마우스를 올린 상태에서 F8을 누릅니다. 업무 버튼은 클릭하지 않습니다.
  2. 선택 창에 나타난 요소 이름과 종류를 확인합니다. 버튼 안의 글자가 잡혔다면 상위 요소 목록에서 실제 버튼을 직접 고릅니다. 잘못 골랐다면 다시 선택합니다.
  3. 이 요소로 선택을 누릅니다. MCP가 현재 화면에서 같은 요소인지 확인하고 저장하며, 채팅에서 학습 완료를 확인합니다. 선택 창이 닫힌 것만으로 저장 완료는 아닙니다.
  4. “배운 신청 상태를 신청으로 바꾸고 적용됐는지 확인해줘.”라고 요청합니다. 이후에도 같은 별명으로 사용할 수 있습니다.

학습 대기 중 같은 요청을 다시 보내도 선택 창을 여러 개 띄우지 않습니다. Esc·취소 또는 채팅의 취소 요청으로 종료할 수 있습니다. 다른 화면 작업은 학습을 끝낸 뒤 진행합니다. 창 표시 실패, 요소 응답 지연, 고유하게 구분하지 못함, 저장 실패를 구분하며 자동으로 학습을 반복하지 않습니다.

UIA는 직접 요소 학습을 지원하는 기본 방식입니다. “UIA라서 선택 창을 지원하지 않는다”는 설명으로 대체하지 않습니다. 다만 프로그램이 Windows에 요소 정보를 제공하지 않거나 같은 요소를 고유하게 구분할 수 없는 경우에는 학습을 완료할 수 없습니다. 요소 목록 조회와 작업 저장은 직접 선택을 대신하지 않습니다.

이 기능은 LLM 재학습이 아니라 이 PC에 요소를 찾는 기준을 저장합니다. 입력 값·스크린샷·좌표·창 번호는 학습 파일에 저장하지 않습니다. 기존 배포본을 새 폴더에 덮어 쓰는 대신 새 ZIP을 모두 압축 풀고, 같은 설정을 유지한 채 연결을 갱신하세요. 연결을 다시 연 뒤 버전 0.9.0과 computer_teach_status 기능을 확인합니다.

자동 검사 582개 실행: 580개 통과, 2개 조건부 제외. 소스 및 내장 Python 배포본에서 기본 computer_teach_element 공개 MCP 경로로 각각 9개·9개 합성 시나리오를 통과했습니다. 선택 창의 실제 표시와 중복 요청, F8 버튼 선택·확인·자동 저장, 3초 선택 방식으로 콤보박스 상위 요소를 직접 고르기, Esc·MCP 취소, 프로그램·MCP 재시작 후 저장 요소 재사용, 실제 프로세스 종료를 확인했습니다. 선택 전에는 Driver의 전체 화면 읽기가 0회였습니다. 학습·취소 과정에서 대상 앱의 값·클릭·키 기록이 변하지 않았고 소유한 선택 도우미가 모두 종료됐습니다. 별도 네이티브 시험 6개도 통과했으며 F8 충돌 시 버튼 방식과 200% 화면 배율의 초기·확인 창을 검수했습니다. 사용자 선택을 자동화한 합성 시험입니다. 실제 사람의 사용성, 사내 프로그램·사내 LLM·관리자 권한 연결의 실제 화면 작업은 검증하지 않았습니다.

0.8.0 이전 구현·검증 기록

아래는 이전 버전의 기록입니다. 현재 학습 방법은 위의 0.9.0 안내를 사용하세요. 0.8.0의 MCP 학습 시험은 요소 번호를 지정하는 경로였으며 F8 도우미는 별도로 시험했습니다. 공개 MCP의 기본 직접 선택부터 저장까지 이어지는 경로는 당시 검증하지 않았습니다.

채팅에서 “신청 상태를 직접 가르쳐줄게. 요소 학습을 시작해줘.”라고 요청하세요. 작은 선택 창이 열리면 실제 프로그램의 입력창·선택 상자·버튼 위에 마우스를 올리고 F8을 누릅니다. 업무 버튼을 클릭하지 않습니다. Esc 또는 취소 버튼으로 그만둘 수 있습니다.

이후 “배운 신청 상태를 신청으로 바꾸고 적용됐는지 확인해줘.”라고 요청합니다. 저장한 이름과 요소의 고유한 식별 정보·상위 영역을 현재 화면과 대조합니다. 창 번호가 달라져도 다시 찾으며, 중복되거나 바뀐 요소는 다시 지정하도록 안내합니다. “배운 요소 목록을 보여줘”, “조회 버튼을 다시 가르칠게”, “배운 조회 버튼을 지워줘”로 관리합니다.

LLM을 재학습하는 방식이 아니라 이 PC에 화면 요소를 찾는 기준을 저장하는 기능입니다. 입력 값·스크린샷·좌표·창 번호는 학습 파일에 저장하지 않습니다. 화면 분류는 정리용 이름이며 화면 일치 증거가 아닙니다. UIA에서 구분할 수 없는 그림 화면·중복 요소는 학습 성공으로 표시하지 않습니다. 전체 작업 녹화 기능은 아닙니다.

요소가 많은 화면은 검색어·상위 영역·조작 가능한 요소·페이지로 목록을 좁힙니다. 찾은 요소는 기존 검증된 입력 도구와 단계 작업에 사용할 수 있습니다. 사용자가 확인하지 않은 드롭다운 순서나 완료 조건을 추측하지 않습니다.

프로그램을 열자마자 닫히는 문제

기존 실행 코드는 MCP 임시 기록 폴더를 작업 폴더로 사용했습니다. 이제 EXE 폴더에서 시작하며 MCP의 Python/Tcl 환경 변수가 업무 프로그램에 섞이지 않게 합니다. 프로세스 생성·조기 종료·실제 창 관찰을 구분하고 불확실한 실행을 자동 반복하지 않습니다. 현재 MCP의 권한을 그대로 상속합니다.

종료 처리 중의 NullReferenceException만으로 최초 원인을 확정할 수 없습니다. 상대 경로 파일을 읽는 합성 실행파일은 이전 작업 폴더에서 실패하고 수정 후 실행되는 것을 확인했습니다. 해당 운영 프로그램과 관리자 권한의 실제 화면 조작 성공은 별도 확인이 필요합니다.

자동 검사 562개 실행: 560개 통과, 2개 조건부 제외. 소스와 내장 Python 배포본에서 실제 MCP·기존 Driver 0.28.2로 각각 5개 합성 화면 시나리오를 통과했습니다. 입력칸·콤보박스 학습과 재사용, 같은 이름의 두 영역 구분, 4개 학습 요소의 저장 내용, 앱 재실행·MCP 재연결 후 새 창에서의 재사용, 원래 프로세스의 실제 종료를 독립 앱 기록과 대조했습니다. 실제 F8 선택·Driver 재관찰 일치·Esc 취소도 시험했으며 업무 입력·선택·버튼·키 처리 횟수는 바뀌지 않았습니다. F8 시험은 자동화한 합성 시험이며 사람의 실제 학습 작업은 별도 확인이 필요합니다. 선택 도우미는 현재 200% 화면 배율에서 검수했습니다. 사내 프로그램·사내 LLM·관리자 연결 경로의 화면 조작 성공을 뜻하지 않습니다.

0.7.1 — 설치 연결 진단과 오류 구분

0.7.0 진단은 Job 객체로 자식 프로세스를 관리하지 못하면 MCP 연결 검사 전 중단했습니다. 또한 stderr를 버려 관리자 승인 취소·시작 실패도 “진단 프로세스 종료”라는 일반 오류로 표시했습니다. 이 메시지만으로 회사 보안 정책 또는 PowerShell 정책 차단을 확정할 수 없습니다.

이제 Job을 사용할 수 없는 환경은 읽기 전용 stdio 연결과 정상 종료를 별도로 검증합니다. 종료가 확인돼야 연결 성공으로 처리합니다. 실제 Job 실패 단계·Windows 오류 번호를 기록하며 UAC 취소·정상 종료 실패·알 수 없는 종료를 구분합니다. Windows 정책이나 관리자 승인 절차를 변경하지 않습니다.

0.7.0의 관리자 실행 코드와 같은 계정·세션 인증 조건은 유지합니다. 실제 관리자 화면 조작 검증은 이전 보고서와 같이 미완료이며, 진단 수정이 관리자 권한 획득을 보장하지 않습니다.

자동 검사 485개 실행: 483개 통과, 2개 조건부 제외. 최종 배포 구성의 연결 프로그램·MCP·기존 Cua Driver 0.28.2로 읽기 전용 연결을 시험했습니다. Job 할당 실패(WinError 5)는 시험에서 주입했으며, 32개 도구·Driver 스키마와 정상 종료(종료 코드 0)를 확인했습니다. 이 시험은 명시적 일반 실행 모드이며 화면 세션이나 업무 앱을 시작하지 않았습니다. 실제 운영 PC의 Job 실패 원인이나 관리자 화면 조작 성공을 증명하는 결과는 아닙니다.

0.7.0 — 관리자 실행 연결

최종 자동 검사: 479개 실행, 477개 통과, 2개 조건부 제외.

일반 클라이언트의 stdio를 유지하며 Windows runas/UAC로 같은 계정의 연결 프로세스와 MCP·Driver를 시작합니다. 새로운 로컬 named pipe, SID ACL, 연결 상대 PID, 같은 계정·세션·실행파일과 임시 확인값을 검사합니다. 원격 연결을 거절하며 서비스·예약 작업·UAC 정책 변경·비밀번호 저장은 사용하지 않습니다.

일반 권한 경로에서 32개 도구, 한글 전체 값 입력, 버튼 1회 결과, 합성 앱의 독립 기록, 실제 종료를 확인했습니다. 시험 도구는 내부 입력기·보조 창을 실제 앱 창과 구분합니다. 실제 업무 프로그램·문서는 사용하지 않았습니다.

관리자 실행 시험은 아직 미확인입니다. Windows 승인 응답을 기다리는 동안 초기 연결 120초 제한 시간이 끝났습니다. 일반 실행 성공을 관리자 상태의 화면 조작 성공으로 설명하지 않습니다. 계정 권한·UAC·회사 정책 중 어느 조건이 승인 응답을 막았는지는 확인하지 못했습니다. 같은 계정의 관리자 승인을 받을 수 있는 환경에서 administrator_validation.py로 MCP 토큰·관리자 시험 앱 입력·버튼·실제 종료를 검증할 수 있습니다.

검증한 이전 배포본만 user/local 범위에서 갱신합니다. 다른 MCP·프로젝트·모델·로그인과 현재 설정을 보존하며, 실패하면 선택한 범위의 원래 연결을 복원합니다. 관리자 실행파일 누락·승인 취소를 일반 연결로 대체하지 않습니다. 원래 종료 검증 기능도 유지합니다.

0.6.0 — 종료 요청 뒤 실제 종료 확인

종료 입력 전에 승인된 현재 창과 원래 프로세스의 식별 정보를 확보합니다. 종료 버튼·단축키를 한 번 전달한 뒤, 닫힌 창의 UIA를 다시 읽는 대신 Windows 창 상태와 유지 중인 프로세스 핸들로 종료 여부를 확인합니다. 종료 응답 오류나 빈 창 목록을 성공으로 간주하지 않습니다.

상태판정
대상 창과 관련 확인창이 사라짐window 범위 완료. 같은 프로그램의 다른 기존 문서나 백그라운드 프로세스는 남을 수 있습니다.
원래 대상 PID의 프로세스 종료 확인process 범위 완료. 이름이 같은 모든 실행 인스턴스나 다른 보조 프로세스까지 종료했다는 뜻은 아닙니다.
저장·종료 확인창 후보가 남음needs_dialog. 현재 팝업을 관찰하고 사용자가 정한 저장·종료 방침대로 처리한 뒤 같은 close_id로 다시 확인합니다. 버튼 문구를 추측해 자동 선택하지 않습니다.
숨김·최소화·종료 취소·지연 종료pending 또는 needs_dialog. 종료 완료가 아닙니다. 확인은 제한 시간 동안 읽기만 반복합니다.
접근 실패·조사 오류·식별 불일치unknown. 성공으로 표시하지 않으며 입력을 반복하거나 강제 종료하지 않습니다.

computer_close는 UIA 기반 종료 요청과 확인을 묶습니다. 메뉴·이미지 조작 등으로 종료할 때는 computer_prepare_close 후 기존 화면 도구를 사용하고 computer_verify_closed로 확인합니다. 저장된 단계 작업에서 종료까지 요구하면 computer_run_task 뒤 이 종료 확인 단계를 수행합니다. 기존 UIA 단계 형식에 새 종료 연산을 추가한 것은 아닙니다.

초기 실제 시험에서는 저장 확인창이 닫힌 뒤 남는 비활성 Windows 입력기 보조 창을 팝업 후보로 오인했습니다. 실제로 표시되거나 활성화된 이력이 없는 특정 입력기 보조 창만 후보에서 제외하며, 전체 원본 창 목록은 유지합니다. 일반적인 숨긴 팝업과 원래 종료 대상은 제외하지 않습니다. 종료 순간 창이 사라져 발생한 일시적 조회 오류도 확인했습니다. 알려진 창 조회 오류만 같은 프로세스 기록으로 제한 시간 안에서 재확인하며, 식별 불일치·핸들 재사용·지속 오류는 성공으로 처리하지 않습니다. 재확인에 성공해도 오류 횟수와 코드를 남깁니다.

확인 ID는 같은 활성 MCP 세션에서만 유효합니다. computer_end는 화면 자동화 세션의 종료이며 업무 프로그램의 종료가 아닙니다. 종료 확인을 끝낸 후 호출합니다. 또한 창이 닫혔다고 파일 저장까지 증명되지는 않으므로 파일 저장 결과는 따로 확인해야 합니다.

전체 자동 검사: 471개 실행, 469개 통과, 2개 조건부 제외. 신규 56개 검사는 원본 프로세스 식별, 팝업 소유 관계 변경, 숨김·최소화, 창/프로세스 범위, 조회 실패, 중지 경합, 일회 입력, 세션 종료와 프로그램 종료 구분을 포함합니다. 실제 MCP/Driver를 사용한 합성 WinForms 앱의 6개 종료 시나리오도 통과했습니다. 사내 LLM과 개인 문서는 사용하지 않았습니다.

실제 시험에서 발견한 주의점

  • 현대 메모장은 Ctrl+S가 백그라운드와 전경 경로 모두에서 거절된 사례가 있습니다. 메뉴를 열고 파일→저장을 실행한 경로는 저장과 다시 열기를 통과했습니다.

선택한 글자만 바꾸기는 검증을 통과하지 못했습니다. 메모장에서 ‘모두 선택’ 후 type_text를 호출해도 기존 내용 뒤에 붙은 사례가 있었습니다. 전체 내용 변경은 set_value로 수행하고 저장한 결과를 비교하는 경로를 안내합니다. 커서 위치 기반 삽입이나 부분 선택 교체를 보장하지 않습니다.

Excel 초기 시험에서는 20행과 합계 2,100이 파일에 저장됐으나 닫기 단축키가 W로 입력됐습니다. 이 시도는 전체 성공으로 계산하지 않았습니다. 합성 파일의 저장되지 않은 W를 버리고 다시 열어 기존 저장값을 확인했으며, 이 과정도 MCP로 수행했습니다.

승인 취소와 긴급중지 시험에서만 별도 Windows 조작 도구로 취소/중지 키를 눌렀습니다. 업무 입력·저장 시험은 이 제품의 MCP를 거쳤습니다. 이미지 모드는 화면 이미지 반환까지만 확인했고 이미지 해석이나 좌표 클릭을 성공으로 계산하지 않았습니다.
