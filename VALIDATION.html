0.7.0 — 관리자 실행 연결

최종 자동 검사: 479개 실행, 477개 통과, 2개 조건부 제외.

일반 클라이언트의 stdio를 유지하며 Windows runas/UAC로 같은 계정의 연결 프로세스와 MCP·Driver를 시작합니다. 새로운 로컬 named pipe, SID ACL, 연결 상대 PID, 같은 계정·세션·실행파일과 임시 확인값을 검사합니다. 원격 연결을 거절하며 서비스·예약 작업·UAC 정책 변경·비밀번호 저장은 사용하지 않습니다.

일반 권한 경로에서 32개 도구, 한글 전체 값 입력, 버튼 1회 결과, 합성 앱의 독립 기록, 실제 종료를 확인했습니다. 시험 도구는 내부 입력기·보조 창을 실제 앱 창과 구분합니다. 실제 업무 프로그램·문서는 사용하지 않았습니다.

관리자 실행 시험은 아직 미확인입니다. Windows 승인 응답을 기다리는 동안 초기 연결 120초 제한 시간이 끝났습니다. 일반 실행 성공을 관리자 상태의 화면 조작 성공으로 설명하지 않습니다. 계정 권한·UAC·회사 정책 중 어느 조건이 승인 응답을 막았는지는 확인하지 못했습니다. 같은 계정의 관리자 승인을 받을 수 있는 환경에서 administrator_validation.py로 MCP 토큰·관리자 시험 앱 입력·버튼·실제 종료를 검증할 수 있습니다.

검증한 이전 배포본만 user/local 범위에서 갱신합니다. 다른 MCP·프로젝트·모델·로그인과 현재 설정을 보존하며, 실패하면 선택한 범위의 원래 연결을 복원합니다. 관리자 실행파일 누락·승인 취소를 일반 연결로 대체하지 않습니다. 원래 종료 검증 기능도 유지합니다.

0.6.0 — 종료 요청 뒤 실제 종료 확인

종료 입력 전에 승인된 현재 창과 원래 프로세스의 식별 정보를 확보합니다. 종료 버튼·단축키를 한 번 전달한 뒤, 닫힌 창의 UIA를 다시 읽는 대신 Windows 창 상태와 유지 중인 프로세스 핸들로 종료 여부를 확인합니다. 종료 응답 오류나 빈 창 목록을 성공으로 간주하지 않습니다.

상태판정
대상 창과 관련 확인창이 사라짐window 범위 완료. 같은 프로그램의 다른 기존 문서나 백그라운드 프로세스는 남을 수 있습니다.
원래 대상 PID의 프로세스 종료 확인process 범위 완료. 이름이 같은 모든 실행 인스턴스나 다른 보조 프로세스까지 종료했다는 뜻은 아닙니다.
저장·종료 확인창 후보가 남음needs_dialog. 현재 팝업을 관찰하고 사용자가 정한 저장·종료 방침대로 처리한 뒤 같은 close_id로 다시 확인합니다. 버튼 문구를 추측해 자동 선택하지 않습니다.
숨김·최소화·종료 취소·지연 종료pending 또는 needs_dialog. 종료 완료가 아닙니다. 확인은 제한 시간 동안 읽기만 반복합니다.
접근 실패·조사 오류·식별 불일치unknown. 성공으로 표시하지 않으며 입력을 반복하거나 강제 종료하지 않습니다.

computer_close는 UIA 기반 종료 요청과 확인을 묶습니다. 메뉴·이미지 조작 등으로 종료할 때는 computer_prepare_close 후 기존 화면 도구를 사용하고 computer_verify_closed로 확인합니다. 저장된 단계 작업에서 종료까지 요구하면 computer_run_task 뒤 이 종료 확인 단계를 수행합니다. 기존 UIA 단계 형식에 새 종료 연산을 추가한 것은 아닙니다.

초기 실제 시험에서는 저장 확인창이 닫힌 뒤 남는 비활성 Windows 입력기 보조 창을 팝업 후보로 오인했습니다. 실제로 표시되거나 활성화된 이력이 없는 특정 입력기 보조 창만 후보에서 제외하며, 전체 원본 창 목록은 유지합니다. 일반적인 숨긴 팝업과 원래 종료 대상은 제외하지 않습니다. 종료 순간 창이 사라져 발생한 일시적 조회 오류도 확인했습니다. 알려진 창 조회 오류만 같은 프로세스 기록으로 제한 시간 안에서 재확인하며, 식별 불일치·핸들 재사용·지속 오류는 성공으로 처리하지 않습니다. 재확인에 성공해도 오류 횟수와 코드를 남깁니다.

확인 ID는 같은 활성 MCP 세션에서만 유효합니다. computer_end는 화면 자동화 세션의 종료이며 업무 프로그램의 종료가 아닙니다. 종료 확인을 끝낸 후 호출합니다. 또한 창이 닫혔다고 파일 저장까지 증명되지는 않으므로 파일 저장 결과는 따로 확인해야 합니다.

전체 자동 검사: 471개 실행, 469개 통과, 2개 조건부 제외. 신규 56개 검사는 원본 프로세스 식별, 팝업 소유 관계 변경, 숨김·최소화, 창/프로세스 범위, 조회 실패, 중지 경합, 일회 입력, 세션 종료와 프로그램 종료 구분을 포함합니다. 실제 MCP/Driver를 사용한 합성 WinForms 앱의 6개 종료 시나리오도 통과했습니다. 사내 LLM과 개인 문서는 사용하지 않았습니다.

저장하지 않고 종료합성 시험에서 명시한 선택만 수행했습니다. 파일이 생성되지 않았고 프로세스가 자연 종료됐습니다.
확인창 없는 직접 종료종료 요청 1회 뒤 원래 창과 프로세스 종료를 확인했습니다.

같은 프로세스의 다른 창이 남음대상 창만 닫히면 window 범위만 완료되고 process 범위는 미완료. 나머지 합성 창을 명시적으로 닫은 뒤에야 process 범위가 완료됐습니다.

소스와 내장 Python을 포함한 0.6.0 배포본에서 각각 6개 시나리오가 모두 통과했습니다. 증거: .data/closure-validation/source-051-r3, .data/closure-validation/bundle-060-final. 배포본에서는 실제 MCP 49회 호출을 수행했고, 원래 프로세스의 종료와 합성 저장 파일을 독립적으로 확인했습니다. 배포본의 종료 뒤 읽기 확인은 약 0.12~0.14초였으며, 전체 49회 도구 호출의 합산 시간은 78.603초입니다. 독립 앱 기록·프로세스 상태와 MCP 결과를 비교했습니다. 최소화·숨김 시험은 살아 있음을 확인한 뒤 검증 도구가 소유한 합성 프로세스만 정리했으며, 그 정리를 정상 종료 성공으로 계산하지 않았습니다. 앞선 실패 source-051-final, source-051-r2도 보존합니다. 종료 뒤 상태 확인은 약 0.11~0.13초, 미완료 대기는 약 1.5초였으나 UIA 관찰과 종료 입력을 합친 호출은 약 5.4~8.2초였습니다. 모든 앱의 속도나 성공을 뜻하지 않습니다.

0.5.0 — 프로그램 공통 기능

실행 경로에 특정 브라우저 이름을 조건으로 두지 않습니다. 사용자가 등록한 실행파일과 현재 창을 기준으로 관찰·입력·검증합니다. computer_inspect는 현재 화면에서 확인된 컨트롤, 고유 선택 기준, 지원 동작 후보를 반환합니다. 체크 상태 지정, 목록·탭·트리·라디오 항목 선택, 더블클릭·오른쪽 클릭, 키·단축키 작업을 추가했습니다.

같은 이름의 입력칸은 within으로 상위 영역을 지정합니다. Driver가 구조화된 결과에서 빠뜨린 상위 영역과 고유 식별자는 전체 원본 트리의 요소 번호·역할·깊이·이름·기존 관계가 일치할 때만 보완합니다. 값·동작·조작 핸들은 원본을 보존하고, 복원된 상위 영역 자체는 조작하지 않습니다.

반복 작업은 program_id + window_ref로 여러 프로그램과 같은 프로그램의 여러 창을 구분합니다. 정확한 제목으로 나중에 열리는 창을 찾는 경우에도 현재 PID 안에서 유일한 창만 연결합니다. 없거나 모호하면 needs_binding으로 멈추며, 해당 단계의 입력은 보내지 않습니다. 재개는 마지막 또는 미확인 결과부터 확인합니다.

최신 배포본 Excel 시험 — 전체 성공으로 판정하지 않음

desktop-60f71980에서 저수준 type_text로 요청한 314159 중 셀에는 31만 반영됐습니다. 새 computer_perform의 창 대상 Enter는 전달됐고 A2 선택은 확인했으나, A1 값 완료 조건이 일치하지 않아 작업을 실패로 판정했습니다. 입력을 반복하지 않았습니다. 원인과 재현 조건은 확정하지 못했습니다.

잘못 입력된 합성 파일의 31은 별도 정리 단계에서 그대로 보존·저장한 뒤 파일 XML로 확인하고 시험 창만 닫았습니다. 이 정리 성공은 원래 작업의 성공 횟수에 포함하지 않습니다. 이후 새 합성 파일 desktop-f7ae16e2에서는 입력 전 foreground_unavailable로 중단돼 입력을 보내지 않았습니다. 두 시험의 합성 창이 남아 있지 않음을 확인했습니다. 두 번째 시험 프로세스의 종료 원인은 확인하지 못했습니다.

재현 도구는 입력 간격 30ms를 명시하고, 편집란에서 전체 문구를 읽어 확인한 뒤에만 Enter를 보내도록 보완했습니다. 마지막 시도는 그 전에 중단됐으므로 이 보완으로 Excel 입력 문제가 해결됐다는 검증은 없습니다. 값이 노출되지 않는 편집란에서는 전체 입력을 확인할 수 없으며, 반복 입력이나 자동 저장으로 넘어가지 않습니다. 이 PC의 Excel 전체 작업이 최신 배포본에서 안정적으로 반복된다고 보장하지 않습니다.

앱마다 다른 부분과 실패 기록

격리된 등록 검사와 대화형 설치·경계 검사를 통과했습니다. 기존 설정 보존, 프로젝트별 등록, Chrome/Edge 구분, 중복 설치 생략, 점검 실패, 파일·경로·완료 기록 변경을 검증했습니다. 단위 검사는 가짜 실행파일과 모의 진단·등록을 사용합니다.

추가로 실제 Driver 0.28.2에서 실행 기능 25개 조회와 화면 세션 없음, 연결 파일 생성, 중복 설치 생략을 확인했습니다. 실제 Claude CLI 2.1.286에서는 별도 임시 프로필과 Git 저장소 밖의 시험 프로젝트로 등록 → 동일 설치 재호출 → 해제를 통과했고, 함께 둔 가짜 기존 연결과 모델 설정이 유지됐습니다. 실제 개인 Claude 설정은 변경하지 않았으며 모델에 요청하지 않았습니다.

Git 하위 폴더에서 상위 저장소에 등록되는 현상도 실제로 발견해, 상위 Git 범위와 다른 폴더를 지정한 경우 등록 전에 멈추도록 보완했습니다. 아래의 화면 조작 결과는 0.2.0 때 수행한 기록입니다. 0.3.0의 사내 모델 대화형 설치 성공이나 전체 화면 업무의 재검증으로 확대하지 않습니다. 새 연결 안내 · Claude용 설치 절차

  • 독립 MCP 단위 검사: 전체 129개 중 128개 통과, 1개 제외, 실패 0개. 수정키 별칭, 긴급 중지 종료 경합의 두 처리 순서, 숨긴 Tk 위젯과 저장소의 연결 검사를 포함한 최종 전체 실행 결과입니다. 제외 항목은 이 Windows 환경에서 생성 권한이 없는 실제 심볼릭 링크 시험입니다. 관련 모의 검사는 통과했습니다.

  • 실제 Driver 진단: 0.28.2 / 서명 확인 / MCP 도구 25개 / 화면 세션 미생성.

실제 시험에서 발견한 주의점

  • 현대 메모장은 Ctrl+S가 백그라운드와 전경 경로 모두에서 거절된 사례가 있습니다. 메뉴를 열고 파일→저장을 실행한 경로는 저장과 다시 열기를 통과했습니다.
  • Excel에서 UIA의 즉시 값 읽기가 성공해도 실제 문서에 반영되지 않는 사례가 있었습니다. 탭과 줄바꿈을 포함한 문자열도 원하는 표로 입력되지 않았습니다. 입력 확정, 셀 주소와 값 재확인, 저장 파일 검증이 필요합니다.
  • 드라이버가 동작을 전달했다는 응답은 업무 완료 판정이 아닙니다. 부분 입력 후 무조건 재시도하면 중복 입력될 수 있으므로 새 화면을 확인해야 합니다.

선택한 글자만 바꾸기는 검증을 통과하지 못했습니다. 메모장에서 ‘모두 선택’ 후 type_text를 호출해도 기존 내용 뒤에 붙은 사례가 있었습니다. 전체 내용 변경은 set_value로 수행하고 저장한 결과를 비교하는 경로를 안내합니다. 커서 위치 기반 삽입이나 부분 선택 교체를 보장하지 않습니다.

Excel 초기 시험에서는 20행과 합계 2,100이 파일에 저장됐으나 닫기 단축키가 W로 입력됐습니다. 이 시도는 전체 성공으로 계산하지 않았습니다. 합성 파일의 저장되지 않은 W를 버리고 다시 열어 기존 저장값을 확인했으며, 이 과정도 MCP로 수행했습니다.

승인 취소와 긴급중지 시험에서만 별도 Windows 조작 도구로 취소/중지 키를 눌렀습니다. 업무 입력·저장 시험은 이 제품의 MCP를 거쳤습니다. 이미지 모드는 화면 이미지 반환까지만 확인했고 이미지 해석이나 좌표 클릭을 성공으로 계산하지 않았습니다.

아직 확인하지 않은 범위

  • 사내 LLM 연결과 업무 판단: 사용자 답변대로 이번 시험에 포함하지 않았습니다. 이미지 방식은 연결한 모델의 이미지 입력 지원도 필요합니다.
  • 특정 사내 프로그램과 실제 업무 데이터, 다양한 PC·해상도·배율·모니터 구성, 보안 제품과의 호환성.
  • 장시간 무인 실행의 안정성, 사람이 동시에 마우스·키보드를 사용하는 상황에서의 충돌 회피.
  • PC 전체 외부 통신 차단. MCP는 외부 모델 API를 호출하지 않고 Driver에 통계·업데이트 비활성 설정을 전달하지만, 네트워크 차단 실증이나 보안 승인을 뜻하지 않습니다.

프로그램 허용 목록은 파일 접근을 완전히 격리하는 장치가 아닙니다. 업무에 도입할 때는 합성 자료에서 저장한 작업을 검증한 뒤 적용하세요. 이번 결과를 모든 프로그램에 대한 성공 보장으로 해석해서는 안 됩니다.

증거와 재현

개발 폴더의 .data/acceptance-20261004에 시도별 결과와 단계 기록, 합성 파일을 보관했습니다. .data/report-review에는 원본 보고서 추출본과 실제 진단 결과가 있습니다. 원문 로그에는 화면의 다른 탭 제목이 들어갈 수 있어 사용자용·소스 ZIP에는 포함하지 않았습니다.

재현용 acceptance_workflows.py와 단위 검사, 빌드 스크립트는 소스 ZIP에 포함합니다. 실제 화면 시험에는 Windows, 해당 앱, 별도 Cua Driver가 필요합니다. 시험 경로와 Driver 위치는 실행 PC에 맞게 지정해야 합니다.
