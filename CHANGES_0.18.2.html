2026-10-18 · COMPUTER USE MCP 0.18.2

앱을 다시 열어도 대상을 찾고,
녹화와 저장 방식을 명확하게.

무엇을 수정했나요?

  • 재실행 뒤 달라지는 입력칸 ID: 같은 이름의 입력칸이 많아도 확인 가능한 라벨 관계와 상위 영역을 함께 저장합니다. 예를 들어 ‘조회 조건 안의 Family’를 매 실행의 새 화면에서 다시 찾습니다. 확인되지 않은 주변 글자나 좌표만으로 다른 입력칸을 고르지 않습니다.
  • 녹화 추가와 교체: 기존 단계가 있으면 ‘기존 단계 뒤에 추가’, ‘선택한 단계 교체’, ‘전체 교체’를 고릅니다. 선택 단계 교체에는 연결된 화면 확인도 포함됩니다. 녹화 취소·가져오기 실패 시 이전 초안은 유지됩니다.
  • 기존 수정과 새 작업 저장: 기존 작업을 열었을 때 저장 방식이 표시됩니다. 이름만 바꾸면 기존 작업 수정이며, 별도 작업을 만들려면 새 이름과 ‘새 작업으로 저장’을 선택합니다.

프로그램 이름에 따른 예외 처리를 추가한 것이 아니라 공통 요소 선택·녹화·재생 경로를 수정했습니다. 별도 엔진 설치나 설정 변경은 필요하지 않습니다.

이번에 실제로 확인한 범위

검사결과
관련 회귀 검사344건 통과. 중복 라벨, 바뀐 ID·인덱스, 모호한 대상 거부, 추가·교체·실패 시 보존, 별도 복사 저장 등을 포함합니다.
복잡한 Windows 시험 앱실제 Version 입력 1단계를 편집창에서 녹화·저장했습니다. 앱 프로세스 완전 종료 후 새 프로세스에서 1→3 입력과 결과 확인에 성공했습니다.
기존 녹화 활용기존 17단계와 이미지를 보존한 별도 복구본을 만들었습니다. 원본 이미지와 현재 요소를 대조해 고친 입력 7단계는 새 앱 프로세스에서 통과했습니다. 기존 원본 파일을 덮어쓰지 않았습니다.
메모장시험 탭의 입력·지우기 저장 작업 2단계 통과. 프로세스 완전 종료 후 새로 열어 같은 작업 2단계 통과. 이번에는 메모장을 새로 녹화한 검사가 아닙니다.
계산기저장 작업의 지우기→2→지우기 3단계 통과. 다시 열린 창에서는 처음에 대상 창 전환으로 중단됐고, 새 창 연결 뒤 같은 실행을 재개하여 3단계 통과했습니다. 공용 창 호스트의 프로세스 종료 성공으로 보고하지 않습니다.
편집창 저장 방식실제 새 작업 저장으로 별도 ID가 생성되고 기존 작업의 이름·내용·버전이 유지되는 것을 확인했습니다. 추가·교체 대화상자도 실제 화면에서 확인했습니다.

원본의 이미지 클릭과 ‘직접 화면 확인’ 단계까지 자동 승인한 것은 아닙니다. 전체 원본 17단계의 무인 재생 완료나 모든 사내 프로그램의 성공을 뜻하지 않습니다. 이전 버전의 숫자 ID만 저장된 작업은 자동 추측으로 바꾸지 않으며, 필요한 단계만 편집창에서 다시 지정할 수 있습니다.

기본 실행 방식의 콤보박스 보완: 활성화와 요소 재확인을 먼저 하고 목록 열기·항목 선택을 대상 지정 방식으로 전달합니다. 목록이 열린 직후 닫히던 현상을 수정한 뒤, 시험 앱 프로세스를 다시 종료·재실행하고 기본 computer_run_task로 복구 입력 7/7단계를 확인했습니다. 소요 시간은 약 21.7초이며 완료 조건을 생략하지 않았습니다. 실제 포인터 이동을 보장하는 방식은 아닙니다.

바로 사용하는 방법

  1. v0.18.2 Release의 Computer-Use-MCP-0.18.2-with-driver.zip 전체를 새 폴더에 압축 풉니다.
  2. INSTALL.md를 채팅에 첨부하고 ‘기존 프로그램·저장 작업·다른 MCP를 유지하고 이 버전으로 연결을 갱신해줘’라고 요청합니다.
  3. 다시 연결된 버전이 0.18.2인지 확인합니다. 다운로드만으로 실행 중인 구버전 연결이 바뀌지는 않습니다.

‘저장한 작업을 열어서 특정 입력값만 바꿔줘’, ‘기존 작업을 유지하고 다른 이름으로 새 작업을 만들어줘’처럼 요청할 수 있습니다. 재생용 이미지와 보완 중 원본의 보존 정책은 0.18.1과 같습니다.
