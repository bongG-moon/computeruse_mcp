Smart U Browser와 FXMenuAgent를 구분해서 연결

0.19.1 이후 개발 소스에 반영한 개선입니다. 설치된 Release나 실행 중인 MCP는 자동 갱신되지 않습니다.

두 Agent 전체를 복제하지 않고, 업무 창 선택과 준비 확인을 별도 모듈로 분리했습니다. 입력 권한 검사, 이미지 좌표 계약, 팝업의 소유 관계 확인, 녹화 및 재생은 공통 엔진을 사용합니다.

사용자가 할 일

  1. 실제로 사용하는 업무 화면을 연 뒤 평소처럼 프로그램을 연결합니다. FXMenuAgent는 현재 실행 중인 SKhynix.SmartFX.ClientFX.MenuAgentHost.4.0.exe를 제어 대상으로 등록합니다. 업데이터나 PNTLauncher를 등록했다는 이유로 이 EXE를 자동 허용하지 않습니다.
  2. 업무 창이 여러 개면 현재 제목을 보고 한 번 선택합니다. 숨겨진 상주 폼을 첫 번째 창이라는 이유로 고르지 않습니다.
  3. computer_process_editor에서 녹화하거나 기존 작업을 엽니다. 새 작업에서 관찰한 MenuAgent 제목 형식과 독립 창 관계가 확인되고 후보가 유일하면 사용자 이름을 제외한 업무 화면 문맥을 함께 저장합니다.
  4. 다음 실행에서는 저장한 문맥으로 현재 창을 다시 찾습니다. 같은 업무 화면이 두 개면 선택을 요구하고, 창이 없으면 중단합니다. 사라진 창의 HWND로 입력하거나 동작을 반복하지 않습니다.

기존 작업은 그대로 사용할 수 있습니다. 창 선택 문맥을 추가하려면 “현재 업무 창을 다음에도 찾도록 이 작업의 창 연결 조건을 저장해줘”라고 요청합니다. 클라이언트가 관찰한 window_selector로 연결한 뒤 해당 참조로 편집창을 열고 새 revision으로 저장합니다. 이전 revision, 이미지와 업무 단계는 보존됩니다. 단순히 기존 작업을 열고 저장하면 새 문맥을 추론해 추가하지 않으며, 기존 준비 조건도 자동으로 덮어쓰지 않습니다.

창의 관계를 다르게 다루는 이유

구조처리
Smart U Browser의 WPF와 WindowsFormsHost현재 호스트 내부의 실제 업무 범위와 관련 팝업을 관찰합니다. 설치된 CefSharp 파일만으로 웹 화면이라고 판단하지 않습니다.
FXMenuAgent의 독립 업무 창동일 PID 안에서도 제목 문맥, 보임, 최소화 여부, 프로세스 수명, 클래스, 스레드와 창 관계로 구분합니다. 원래 창이 남아 있어도 명시한 새 업무 창이나 이미 열린 창을 연결할 수 있습니다.
드롭다운, 검색 모달, 중첩 메뉴업무 창 선택으로 소유 관계 검사를 우회하지 않습니다. 목록을 열거나 메뉴가 재생성된 다음 새 관찰을 사용합니다.
ToolStrip과 내부 업무 Form/ElementHost동일한 ‘조회’가 있어도 관찰한 조상 범위를 함께 지정합니다. 도구모음 순번, 정적 command.Id나 WinForms 필드 이름을 실제 AutomationId로 추정하지 않습니다.

현재 자동 독립 창 선택은 관찰된 owner=0과 root_owner=self를 요구합니다. WinForms가 숨겨진 framework owner를 만드는 경우에는 정적 Owner 미지정만으로 자동 허용하지 않으며, 현재 관찰한 창을 명시적으로 연결해야 합니다. 이 경우 자동 저장 문맥은 생성되지 않을 수 있습니다.

동적 준비 상태와 실행 속도

창이 보이는 것과 실제 업무 컨트롤이 붙고 명령이 활성화되는 것은 별개입니다. 필요한 경우에만 ready_when으로 다음 동작에 필요한 요소의 존재, 활성화, 표시 또는 값을 범위 조회합니다. 툴바가 없는 화면에 툴바 생성을 강제하지 않습니다.

기본 실행에는 준비 대기나 전체 UIA/MSAA 진단을 추가하지 않습니다. 명시한 준비 조건은 연결 또는 새 작업 시작 때만 검사하고, 같은 run을 이어갈 때는 시작 상태를 다시 요구하지 않습니다. Provider 오류, 불완전한 읽기, 중복 대상은 준비 완료로 처리하지 않습니다. 준비 완료는 업무 성공이 아닙니다.

읽기는 기본 2초, 최대 10초 제한이며 고정 sleep으로 시간을 늘리지 않습니다. 범위 조회는 대상 식별을 위해 창의 메타데이터를 탐색할 수 있지만 전체 Driver 트리를 여러 번 수집하거나 모델을 호출하지 않습니다.

연결 담당 클라이언트용 예시

아래는 설명용 구조입니다. 제목, 클래스와 selector는 반드시 현재 관찰한 값으로 구성합니다. 사용자가 JSON이나 설정 파일을 직접 작성할 필요는 없습니다.

{
  "program_id": "등록한-업무-프로그램",
  "window_selector": {
    "title_prefix": "Device Setup Standard (CJTEST) - [smartMMDM, "
  },
  "ready_when": {
    "controls": [{
      "selector": {"name": "조회", "within": {"name": "관찰한 업무 영역"}},
      "enabled": true,
      "visible": true
    }],
    "timeout_ms": 2000
  }
}

선택자가 같은 창이 여럿이면 반환된 후보 중 실제 window_id를 명시합니다. 이 ID는 현재 연결에만 사용합니다. 저장 문맥에는 PID, HWND, RuntimeId, 요소 인덱스를 넣을 수 없습니다.

입력 후 다른 독립 업무 창의 결과를 확인해야 하는 동작은 window_transition={"mode":"business_window","window_selector":{...}}를 사용합니다. 새 창이 열렸다는 사실만으로 성공하지 않고 기존의 구체적인 완료 조건을 검사합니다. 일반 auto/new_window 전환과 팝업 대기의 의미는 유지합니다.

실제 관찰에 연결한 SmartFX 특화 처리

smartfx_profiles.py는 승인된 현재 실행 파일로 두 호스트 유형을 구분합니다. 사용자가 프로필을 설정하거나 별도 Agent를 설치할 필요가 없습니다. 공통 엔진에서 실제로 반환된 업무 영역, 조건 영역, ToolStrip, 표와 속성 편집기의 메타데이터와 조상 관계를 읽습니다.

같은 ‘조회’가 툴바와 업무 본문에 있으면 실제 관찰한 영역으로 선택 범위를 좁힙니다. 숫자 AutomationId보다 재식별 가능한 이름과 고유 영역을 우선하며, 모호하면 기존 공통 검증이 중단합니다. gcboFamily 같은 정적 필드명, 현지화 키, 내부 코드값을 실제 AutomationId나 표시값으로 만들어 내지 않습니다.

대화형 select_option도 펼침 직전과 직후의 네이티브 창 관계를 비교합니다. 임베디드 자식 HWND가 소유하는 목록과 숨겨졌다 다시 보인 동일 HWND를 확인하고, 별도 검색 모달과 여러 후보는 자동 선택하지 않습니다. 실제 HWND가 있지만 Driver가 읽지 못하면 combo_popup_driver_unavailable로 구분하며 입력을 반복하지 않습니다.

녹화된 MenuItem, ListItem, DataItem 클릭은 최신 Driver 관찰, 실제 클릭 기능, 안정적인 선택자가 확인되면 이미지 대신 요소 클릭으로 보존합니다. 메뉴를 다시 열어 ID가 바뀌어도 현재 관찰로 재식별하며, 기존 결과 확인과 명시적 사람 승인은 유지합니다.

특화 영역 정리는 이미 받은 트리를 한 번 색인하여 재사용합니다. 매 단계에 전체 진단, 캡처, 모델 호출이나 준비 대기를 추가하지 않습니다. 편집창의 명시적 요소 진단에는 호스트 전략을 로컬 보고서에 함께 남깁니다.

진단과 제한

Provider와 Driver 사이의 누락, 원본 UIA 및 MSAA, 범위와 패턴 확인은 요소 진단 안내를 사용합니다. 진단과 새 문맥은 data_policy=local의 로컬 보존 경계를 유지하며 새 네트워크 전송이나 별도 모델 API를 만들지 않습니다.

독립 업무 창을 연결하는 기능과 녹화 도중 새 독립 업무 창을 자동 편입하는 기능은 다릅니다. 후자는 아직 지원하지 않아 명시적 연결과 단계 구성이 필요합니다. 가상 표 셀의 Realize/ScrollItem 실행 및 임의의 동적 PropertyGrid 편집도 완성된 것으로 간주하지 않습니다. 지원 패턴 진단만으로 실행 성공을 보장하지 않습니다.

제목 없는 WinForms 808 검색 모달에 구별 가능한 근거가 없다면 클래스만으로 종류를 확정할 수 없습니다. 이름 없는 목록의 표시값과 내부 코드값도 자동으로 동일시하지 않습니다. 기존 녹화본을 조용히 다시 작성하거나 사람 확인을 자동 승인하지 않습니다.

시험 범위는 자체 WinForms/ElementHost 앱과 실제 offscreen HWND의 소유 경로입니다. 사내 벤더 DLL, 실제 Family/상태 값 선택, 운영 녹화의 전체 재생과 Excel 생성은 별도 검증 대상입니다. 시험 앱의 100/125/150% 콘텐츠 크기 변경은 실제 OS DPI나 멀티모니터 시험과 동일하지 않습니다.
