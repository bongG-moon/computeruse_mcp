드롭다운 팝업 재생 수정

2026-10-19 · Computer Use MCP 0.18.3 변경 안내

보고된 현상: 드롭다운은 열리지만 다음 항목 선택으로 이어지지 않음. 운영 원본 receipt 및 실제 사내 앱에 접근하지 않았으므로 운영 장애의 단일 원인은 확정하지 않았습니다.

변경내용
팝업 식별정형 WinForms 클래스의 실행별 app-domain 접미사 변화 허용. 컨트롤 종류·스타일, 제목, 동일 프로세스, 소유 관계, 표시 상태 및 후보 유일성은 유지합니다. 기존 저장 작업에도 재녹화 없이 적용되는 실행기 수정입니다.
실패 진단기존 recording_window_missing 코드는 유지하면서 관찰 후보와 not_visible/title_mismatch/class_mismatch/owner_mismatch를 반환합니다. 관찰되지 않은 경우와 조건 불일치를 구분합니다. 잠깐 열렸다 닫힌 사실까지 확정하는 이벤트 추적 기능은 아닙니다.
중간 확인창opened_from 팝업 확인창에만 비활성 표시·마우스 클릭 시 비활성 정책을 적용합니다. 사람이 확인해야 한다는 조건은 유지하며 확인을 자동 생성하지 않습니다. 실제 Windows 포커스 유지 효과는 추가 실기 검증이 필요합니다.
원본·이어가기녹화 원본과 이미지·단계 순서를 수정하지 않습니다. 화면 표시용 옵션은 실행 기록 스키마에 저장하지 않아 기존 이어가기 형식을 유지합니다. 불확실한 클릭을 자동 반복하지 않습니다.

검증

회귀 테스트 137개 통과. recording_windows, workflow_windows, client_compatibility, workflows, workflow_visual_review, replay_readiness 모듈을 실행했습니다. 확인창 C# 빌드도 통과했습니다.

커스텀 WinForms 클래스가 재실행 시 바뀌는 경우의 팝업 연결, 중복·다른 프로세스·다른 소유 창 차단, 이미지 열기→사람 확인→항목 클릭→부모 창 복귀 및 이어가기에서 입력이 반복되지 않는 흐름을 모의 런타임으로 검증했습니다. 이것은 실제 업무 앱을 조작한 결과가 아닙니다.

이 PC 오류와의 구분

초기 테스트는 샌드박스 임시 폴더 접근 오류로 실패했습니다. 정상 권한에서 재실행해 통과했습니다. 최근 Windows 기록에는 개발 도구 샌드박스 오류도 있었으나, 사용자에게 표시된 오류창과 동일한 원인인지 확정하지 않았습니다. Windows 보안 정책이나 사용자 설정은 변경하지 않았습니다.

운영 앱 실제 재생, 비활성 확인창의 실제 드롭다운 유지 여부, 사용자 오류창의 정확한 원인은 미검증입니다. UIA 선택값 자동 추출 범위를 확대한 변경은 아닙니다. 이 수정은 v0.18.3 배포본에 포함됩니다.
