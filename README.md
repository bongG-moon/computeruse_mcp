**새 파일 다운로드와 현재 연결 갱신은 다릅니다.** 이전 MCP와 편집창을 계속 사용하면 이전 기능이 남습니다. 저장할 내용을 먼저 정리한 뒤 새 연결에서 편집창을 여세요. 제품 갱신에는 재연결이 필요하지만, 연결 후 프로그램만 추가할 때마다 재연결하지는 않습니다.

## 가장 쉬운 사용 순서

1. **프로그램 열기** — 평소 방법으로 앱을 열고, 반복할 업무의 시작 화면까지 이동합니다.
2. **녹화 열기** — 채팅에 “지금 열린 프로그램을 등록하고 프로세스 편집창을 열어줘”라고 요청합니다. 이미 등록됐다면 그대로 사용합니다.
3. **직접 작업하기** — **● 동작 녹화 → 기록 시작**을 누르고 실제 클릭·입력을 수행합니다. 기록 중 창은 작아지며 **접어두기**로 숨길 수 있습니다. Esc로 일시정지합니다.
4. **검토하고 저장하기** — **기록 마치고 검토**에서 순서·인식 방식·입력값을 확인합니다. 보완할 단계는 두 번 클릭해 **이 단계만 다시 지정**으로 고칩니다. 바로 이미지를 고르려면 **이미지로 다시 지정**을 누릅니다. 전체 녹화를 다시 할 필요는 없습니다.
5. **실행하기** — 시작 화면을 준비하고 “저장한 ‘반복 조회’를 실행해줘”라고 요청합니다. 화면 확인 창이 나타나면 실제 결과를 보고 **확인 완료** 또는 **결과가 다름**을 선택합니다.

**녹화 중 사용자의 클릭과 입력은 실제 프로그램에 적용됩니다.** 녹화 취소는 이미 수행한 업무를 되돌리지 않습니다. 요소만 고르는 수동 편집과 저장 자체는 작업을 재실행하지 않습니다.

## 0.15.0에서 달라진 점

- **버튼도 요소로 기록합니다.** 실제 조작 도구에서 같은 버튼을 확인한 경우 UIA 클릭으로 저장합니다. 이름 없는 사용자 정의 화면은 이미지나 보완할 단계로 남습니다.
- **빠른 클릭과 붙여넣기를 보완합니다.** 마우스를 오래 올려놓지 않고 클릭한 일반 Windows 버튼도 실제 클릭한 컨트롤을 대조합니다. 읽을 수 있는 비보호 입력칸의 붙여넣기는 적용된 값으로 기록합니다.
- **가리는 표시를 이미지에 섞지 않습니다.** 다른 창이나 커서 표시 도구가 겹치면 대상 프로그램 자체의 이미지로 캡처를 시도합니다. 앱이 응답하지 않거나 빈 이미지가 나오면 보완할 단계로 남깁니다.
- **중간 입력값을 보존합니다.** 같은 칸을 `W → N`으로 바꾸는 동작은 관찰 증거와 현재 요소가 확인될 때 각 단계의 값으로 저장합니다. 선택값이 보인다는 이유만으로 지원되지 않는 입력 방법을 추측하지 않습니다.
- **녹화 전에 재생 조건을 점검합니다.** 이미지 캡처와 좌표 조건을 확인하고 지원되지 않는 창은 요소 방식만 기록합니다. DPI 비인식 앱은 측정된 100% 배율·좌표 대응을 충족할 때만 이미지 입력을 허용합니다. 레지스트리를 자동으로 바꾸지 않습니다.
- **지연된 요소 읽기를 복구합니다.** 한 번의 응답 지연으로 녹화 전체의 요소 읽기를 영구 중단하지 않습니다. 응답하지 않는 창의 동시 읽기를 제한하고, 응답이 돌아오면 재개합니다.
- **입력하지 못한 단계부터 이어갑니다.** 전달되지 않았다는 기록이 있는 경우 같은 실행에서 준비 상태를 다시 확인하고 해당 단계부터 진행합니다. 완료한 앞 단계를 다시 실행하지 않습니다. 전달 여부가 불명확하면 결과 확인부터 합니다.
- **텍스트 전용 모델도 기본으로 연결합니다.** 모델에 이미지를 자동 전달하지 않습니다. 저장된 이미지 비교는 PC 안에서 수행하고, 사람 확인은 PC의 화면 확인 창을 사용합니다. 모델이 이미지를 이해했다고 보고하지 않습니다.

## 새로운 프로그램은 채팅으로 추가하세요

> 지금 열린 ‘내 업무 프로그램’을 자동화 대상으로 추가해줘. 같은 이름이 여러 개면 창 제목으로 구분해서 보여줘.

실행 주소만 알고 있다면 주소를 알려주면 됩니다. 주소를 여는 프로그램과 실제 업무 창이 다른 경우 **실제 업무 창을 목록에서 선택**합니다. 설정 파일을 찾거나 레지스트리를 편집할 필요가 없습니다. 등록은 프로그램 실행이나 모든 화면의 인식 성공을 뜻하지 않습니다.

## 멈췄을 때는 전체를 다시 시작하지 마세요

> 방금 중단한 실행을 이어가고 싶어. 입력 전달 여부와 현재 화면부터 확인하고, 입력하지 못한 단계만 같은 실행에서 진행해줘. 완료한 앞 단계는 반복하지 마.

첫 버튼을 찾지 못하면 업무 시작 화면이 맞는지 먼저 확인합니다. 창을 다른 모니터로 옮겼다는 이유만으로 재녹화하지 않습니다. 실제 이미지 모양·배율·후보 수 등의 진단을 확인하고 필요한 단계만 다시 지정합니다. 이미 보낸 입력을 무작정 반복하지 않습니다.

## 이전 0.14.0의 변경 기록

아래 버전별 설명은 당시의 변경 기록입니다. 현재 이미지 전달 기본값과 녹화 사용 방법은 위의 0.15.0 안내를 따릅니다.

- UIA 정보가 부족하면 같은 창의 이미지를 함께 제공합니다. 별도 세션 전환 없이 읽을 수 있으며 입력 권한은 그대로입니다.
- 실행 중 현재 단계와 화면 읽기·입력·결과 확인 상태를 제공합니다. `computer_activity`는 긴 실행이 끝나기 전에도 답합니다. 자동 표시 여부는 MCP 클라이언트에 따라 다릅니다.
- `computer_inspect`의 `within`으로 고유한 상위 영역을 지정하면 부모 식별 정보는 전체 창에서 확인하고 값·패턴 읽기는 해당 하위 영역으로 줄입니다. 읽기 전용 조사 결과이며 Driver의 클릭 핸들로 사용하지 않습니다.
- 이미지 단계에 **완료 요소와 예상 값**을 지정하면 전후 변화까지 새로 확인한 뒤 자동 진행합니다. 조건을 지정하지 않았거나 확인할 수 없으면 기존 화면 확인을 유지합니다. 불확실한 입력은 재전송하지 않습니다.
- 동작 녹화가 같은 프로세스에서 원래 창이 연 팝업을 함께 저장합니다. 다음 실행 때 팝업을 새로 찾아 연결합니다. 무관한 창·모호한 후보는 제외합니다.

> 이미지가 이 채팅에서 읽히는지 먼저 확인해줘. 현재 프로그램의 프로세스 편집 창을 열어줘. 이미지로 클릭한 뒤에는 내가 지정한 완료 요소의 값이 실제로 바뀌었는지 확인하고 이어서 실행하도록 만들어줘.

`computer_check_image`는 업무 화면 대신 시험 이미지로 전달 경로를 확인합니다. 성공은 그 이미지의 전달·응답에 한정되며 사내 LLM의 일반적인 화면 인식 정확도를 보증하지 않습니다. [쉬운 변경 안내](CHANGES_0.14.0.html) · [학습·녹화 안내](PROCESS_GUIDE.html)

팝업을 이미지로 닫은 뒤 입력 응답까지 확인되면 원래 창의 화면 확인 단계로 돌아갑니다. 입력 응답 자체가 불명확하면 자동 진행하지 않고 현재 결과를 다시 확인하도록 안내합니다. 팝업이 사라졌다는 이유만으로 같은 클릭을 반복하거나 업무 성공을 선언하지 않습니다.

같은 드롭다운을 다시 열어도 각 열기·선택을 별도 순서로 기록합니다. 이미지 클릭으로 팝업을 열면 팝업이 나타날 때까지 기다린 뒤 해당 화면을 확인합니다. 녹화 중 이미지를 확보하지 못한 항목은 직접 보완할 단계로 표시하며, 저장 전에 해결해야 합니다.

## 0.13.0: 프로그램 추가와 창 전환을 간단하게

**다른 프로그램 추가는 채팅에서 부탁하세요.** 설정 파일을 찾거나 명령어를 입력할 필요가 없습니다.

> 지금 열려 있는 ‘내 업무 프로그램’을 자동화 대상으로 등록해줘. 같은 이름이 여러 개면 목록을 보여줘.

실행파일 경로를 알고 있다면 경로와 필요한 실행 인자를 알려줘도 됩니다. 등록 후 같은 MCP 연결의 다음 화면 작업부터 쓸 수 있습니다. 진행 중인 작업에 새 앱을 임의로 끼워 넣지는 않습니다. 등록했다고 프로그램을 실행한 것은 아닙니다.

**버튼을 누른 뒤 창이 바뀌면 결과부터 확인합니다.** 기존 창이 없어졌을 때 관련된 새 창을 제한시간 안에서 찾아 완료 조건을 확인합니다. 결과가 확인되면 이어서 진행하고, 후보가 여러 개면 선택할 대상을 알려줍니다. 이미 보낸 클릭을 다시 보내지 않습니다. 프로그램 종료는 별도의 종료 확인을 사용합니다.

> 실행 버튼을 누르고 다음 화면의 ‘준비 완료’가 확인되면 이어서 진행해줘. 창이 바뀌어도 버튼을 다시 누르지 말고 현재 결과부터 확인해줘.

**커서가 움직이지 않아도 요소에 직접 동작을 요청할 수 있습니다.** 기본 배경 실행은 그대로이며, 요소 선택·녹화를 방해하던 Driver 커서 표시는 꺼져 있습니다. 결과에서 요청한 입력 방식, Driver가 보고한 처리 방식, 대상과 확인 단계를 구분합니다. `foreground`는 창을 앞으로 가져오는 방식이며 커서 이동 애니메이션을 보장하지 않습니다.

처음 연결하거나 제품 버전을 갱신할 때는 MCP 재접속이 필요합니다. **0.13.0의 등록 도구로 앱만 추가할 때는 재접속하지 않습니다.** [쉬운 변경 안내](CHANGES_0.13.0.html)

## 처음 연결하기

연결 시작 때 Windows UAC 창이 나타나면 같은 로그인 계정의 관리자 권한으로 허용하세요. Claude Code 전체를 관리자 권한으로 실행할 필요는 없습니다. 기존 연결은 새 배포본의 **이전 버전 연결 확인·갱신** 또는 `INSTALL.md`의 범위별 갱신 방법을 이용합니다.

1. 권장 ZIP을 내려받아 **유지할 폴더에 모두 압축 풉니다.** ZIP 안에서 바로 실행하지 마세요. 연결 후에는 이 폴더를 옮기거나 삭제하지 않습니다.
2. 압축 푼 `Computer-Use-MCP` 폴더에서 **Computer Use MCP 설정.exe**를 두 번 누릅니다.
3. **1 연결 준비 → Driver 파일 선택**에서 동봉된 `driver\cua-driver.exe`를 선택합니다. 이미 올바른 경로가 표시되어 있으면 그대로 사용합니다. **연결 확인 (화면 조작 없음)**을 눌러 확인합니다.
4. **2 사용할 프로그램**에서 쓸 프로그램을 확인합니다. 다른 앱은 **프로그램 추가 → 파일 선택**으로 실제 `.exe`를 고릅니다. 위치를 모르면 앱을 먼저 열고 **열린 창에서 선택**으로 고를 수 있습니다. 원하는 이름을 적고 **저장**합니다.
5. **1 연결 준비 → 저장하고 Claude Code에 연결**을 누릅니다. 이 버튼은 현재 사용자 전체의 Claude Code 연결을 등록합니다. 특정 작업 폴더에서만 쓰려면 아래의 채팅 설치 방법을 사용하세요.
6. Claude Code를 다시 열고 `/mcp`에서 `local-computer-use` 연결을 확인합니다. 먼저 새 시험 문서로 작은 작업을 요청하세요.

> 메모장의 새 시험 문서에 ‘자동화 연습 123’을 입력해줘. 다시 읽은 전체 내용이 정확히 같은지 확인한 뒤 멈춰줘.

설정 창은 연결 후 닫아도 됩니다. MCP가 필요할 때 동봉 Driver를 실행합니다. 별도의 Driver 창을 계속 열어 둘 필요는 없습니다. 새 설정의 기본 승인 방식은 이 MCP 자체의 시작·조작 팝업을 생략하며, Claude Code의 승인 여부는 Claude Code 설정에 따릅니다.

### Claude Code에 설치를 부탁하기

압축 푼 폴더의 [INSTALL.md](INSTALL.md)를 Claude Code에 첨부하고 아래처럼 요청할 수도 있습니다. 사용자에게 PowerShell 명령이나 JSON 편집을 요구하지 않는 설치 안내입니다.

> 이 안내대로 화면 작업 기능을 연결해줘. Driver는 이 배포 폴더의 driver/cua-driver.exe야. 메모장과 내가 지정하는 프로그램을 사용하고, 이 작업 폴더에서만 쓰고 싶어. 없는 정보만 물어봐줘. 아직 화면을 읽거나 조작하지 마.

기존 연결에 다른 앱을 추가하는 방법도 `INSTALL.md`와 사용 안내에 있습니다. 새 앱을 등록했다고 그 앱의 모든 화면을 자동으로 읽거나 조작할 수 있는 것은 아닙니다.

## 화면을 읽는 방식과 결과 확인

- **버튼·글자 정보(UIA)**: Windows가 제공하는 버튼 이름, 입력칸, 선택 상태 등을 읽습니다. 처음에는 이 방식으로 확인합니다.
- **이미지로 저장한 대상**: 이 PC에서 현재 화면과 저장된 이미지를 비교해 찾습니다. 비전 LLM 없이도 사용할 수 있습니다. 사람이 확인할 화면은 PC의 별도 확인 창에 표시합니다.
- **모델의 이미지 해석**: 연결된 모델과 클라이언트가 이미지 입력을 지원할 때만 별도로 켭니다. 기본 연결에서는 모델에 이미지를 보내지 않습니다.

이 MCP에는 LLM이 들어 있지 않습니다. 모델은 연결한 클라이언트의 설정을 사용합니다. 사내 LLM까지 연결한 상태는 이번 검증 범위에 포함되지 않았습니다. 화면 내용·이미지는 연결한 클라이언트와 모델로 전달될 수 있으므로, 실제 외부 통신 여부는 그 연결 구성을 확인해야 합니다.

**클릭이나 입력이 전달됐다는 응답만으로 업무 완료를 판단하지 않습니다.** 선택값·입력 내용·저장 파일 등 필요한 결과를 다시 확인해야 합니다. UIA를 제공하지 않는 화면, 높은 권한의 앱, 사용자 정의 화면 등은 제약이 있으며 이미지 방식도 모든 앱의 성공을 보장하지 않습니다.

## 작업 후 종료까지 확인하기

0.7.1은 종료 요청 전에 원래 창·프로세스를 확인하고, 종료 후 상태를 다시 읽습니다. 저장·종료 확인창이 남으면 완료로 처리하지 않습니다. 숨김·최소화와 실제 종료를 구분하고, **특정 창이 닫혔는지**와 **원래 프로세스가 종료됐는지**도 구분합니다.

> 작업이 끝나면 지정한 시험 파일에 저장하고 프로그램을 종료해줘. 저장·종료 확인창도 처리하고 실제 종료됐는지 확인해줘.

저장 또는 버리기 방침이 불명확하면 임의로 선택하지 않습니다. 저장 내용 확인은 종료 확인과 별도이며, 저장이 목적이면 파일을 다시 열어 내용까지 확인해야 합니다. `computer_end`는 화면 작업 세션을 끝내는 기능이고 앱 종료 확인을 대신하지 않습니다.

## 0.12.0: 한 번 배운 작업을 빠르게 반복하기

처음에는 필요한 요소와 완료 조건을 확인해 작업을 저장하고 실행합니다. **저장된 조건까지 모두 확인한 실행이 한 번 성공하면, 다음부터 같은 작업은 자동으로 빠른 반복 경로를 사용합니다.** 버튼마다 채팅으로 새 명령을 만드는 대신 MCP가 저장된 순서를 이어서 실행하고, 전체 화면 대신 대상과 관련된 정보를 우선 읽습니다.

> 저장한 ‘반복 조회 작업’을 실행해줘. 처음에는 결과까지 확인하고, 이후 같은 작업은 검증된 방법으로 빠르게 반복해줘. 예상과 다르면 멈추고 어느 단계인지 알려줘.

- 기본값은 `computer_run_task`의 `execution_mode: "auto"`입니다. 처음 실행, 작업 순서·변수 구성·프로그램 설정·실행파일이 달라진 경우에는 일반 경로로 확인합니다. 이번 입력값만 바꾸는 작업은 저장한 변수에 새 값을 넣고, 새 실제 값으로 검증합니다.
- **빠른 반복도 각 동작의 적용 결과를 확인합니다.** 옛 화면 번호·좌표를 그대로 재생하거나 결과 확인을 생략하지 않습니다. 실행 결과의 `execution.mode`에서 `standard` 또는 `fast`를 구분할 수 있습니다.
- 실패하거나 확인하지 못한 실행은 빠른 반복 자격을 해제합니다. 실패한 입력을 자동으로 다시 보내지 않습니다. 다음 실행은 다시 일반 경로에서 확인합니다.
- “이번에는 일반 방식으로 다시 확인해줘”라고 요청하면 `execution_mode: "standard"`를 사용합니다. 중단한 작업을 이어갈 때도 현재 화면부터 새로 확인합니다.
- 이미지 자동 완료 조건은 실행할 때마다 새로 검사합니다. 직접 화면 확인 단계도 그대로 남으며 과거 확인을 이번 확인으로 대신하지 않습니다.

실제 프로그램의 서버 조회 시간과 작업에 저장한 **고정 대기**는 남습니다. 불필요한 고정 대기는 **완료 조건이 될 때까지 대기**로 바꾸세요. 조건이 맞으면 즉시 다음 단계로 진행하고, 제한 시간 안에 맞지 않으면 멈춥니다. 자동으로 모든 대기 시간을 줄이지는 않습니다.

### 이전부터 보이던 완료 문구를 성공으로 인정하지 않기

> 조회 버튼을 누르기 전 상태와 비교해서, 이번 조회 결과가 새로 표시됐는지 확인해줘. 예전부터 있던 ‘완료’ 문구만으로 성공 처리하지 마.

완료 조건에는 `require_change: true`를 지정할 수 있습니다. 동작 직전의 기준 상태와 달라졌는지 확인하므로 이미 있던 같은 값만으로 통과하지 않습니다. 실제로 변하는 결과 번호·건수·상태를 선택해야 합니다. 매번 같은 문구만 제공하는 화면은 그 문구만으로 새 조회를 증명할 수 없습니다. `wait_for_state`는 지정한 조건을 제한 시간 동안 확인하며, 변화 기준을 확보하지 못하면 성공으로 처리하지 않습니다.

### 녹화는 초안과 누락 안내를 함께 확인하기

**요소 위에 마우스를 올린 기록, 요소를 가르친 기록, 실제 동작을 녹화한 기록은 다릅니다.** 연속 작업은 프로세스 편집 창의 **동작 녹화**에서 만드세요. 녹화 상태와 기록 수를 확인하고 **기록 마치고 검토**로 끝냅니다.

지원되는 입력·체크 상태는 요소와 최종값을 대조해 단계로 정리합니다. 콤보박스는 최종값이 보이더라도 실제 입력·선택 확정 방법을 확인하지 못하면 자동 선택으로 추측하지 않습니다. 해당 단계는 직접 요소·동작을 지정해야 합니다. 이미지 동작은 완료 요소의 전후 변화를 자동 확인하도록 지정하거나, 사람이 결과를 확인하는 단계를 사용할 수 있습니다.

새 팝업·허용 범위 밖의 창·기록 오류 등으로 일부가 빠졌으면 **부분 기록과 누락 이유**를 표시합니다. 누락 안내를 확인하고 필요한 단계를 직접 추가하거나 삭제한 뒤 저장합니다. 누락 안내 확인은 잃어버린 동작을 자동으로 복원하거나 업무 성공을 승인하는 기능이 아닙니다.

### 주소나 바로가기로 여는 프로그램 등록하기

설정 창의 **프로그램 추가/수정 → 여는 방법 · 선택**에서 지정합니다. 보통 EXE만 여는 앱은 비워 두면 됩니다.

| 항목 | 입력할 내용 |
| --- | --- |
| 실행파일 | 실제 업무 창을 소유하는 `.exe`. 위치를 모르면 앱을 직접 연 뒤 ‘열린 창에서 선택’ 사용 |
| 실행 주소 | 설치된 앱의 전용 `protocol://...` 주소 또는 `http(s)://...` 주소 |
| EXE 실행 인자 | 바로가기에 필요한 인자가 있으면 **한 줄에 한 개씩** 입력. 예: `--from-shortcut` |
| EXE 시작 폴더 | 앱이 지정 폴더에서 시작해야 할 때 입력. 비우면 EXE 폴더 사용 |
| 추가 조작 실행파일 | 처음 연 앱과 실제 업무 창의 실행파일이 다를 때 지정 |

주소 실행과 EXE 인자·시작 폴더는 함께 지정하지 않습니다. 주소를 Windows에 전달했다는 결과와 실제 업무 창이 준비됐다는 결과는 구분합니다. 운영체제의 해당 주소 연결이 준비되어 있어야 하며, 로그인 화면은 별도로 확인합니다.

MCP 등록 도구는 `launch_uri`, `arguments`, `working_directory`를 지원합니다. 로컬 유지보수 도구에서는 `programs.py`의 `--launch-uri`, `--argument=--flag`, `--working-directory`를 지원합니다. `install.py inspect/prepare`에서는 정확히 하나의 `--app-exe`에 `--app-launch-uri`, `--app-argument=--flag`, `--app-working-directory`, `--app-control-exe`를 연결합니다. 일반 사용자는 다음처럼 요청하면 됩니다.

> 이 앱은 EXE를 직접 여는 대신 내가 알려주는 주소로 열어야 해. 실제 열린 창에서 실행파일을 확인해서 등록하고, 그 주소를 여는 방법으로 저장해줘. 기존 프로그램 설정은 유지해줘.

### 내보낸 결과 파일을 정확하게 확인하기

> 결과 폴더는 내가 지정할게. 엑셀로 내보내기 전에 그 폴더의 기존 파일을 기록하고, 이번에 만든 파일에서 ‘분류’ 열의 모든 데이터가 ‘W’인지 확인해줘. 시트나 헤더가 불명확하면 추측하지 마.

1. **내보내기 전** `computer_prepare_result`로 알고 있는 정확한 결과 폴더와 파일 이름 조건을 지정합니다. 하위 폴더나 PC 전체를 검색하지 않습니다.
2. 요청한 내보내기를 실행합니다. 준비 기능 자체는 엑셀 버튼을 누르거나 파일을 만들지 않습니다.
3. `computer_verify_result`에 받은 `ticket_id`, 정확한 파일 이름, 열 이름, 예상값을 전달합니다. 필요한 경우 헤더 행과 시트 이름도 지정합니다.
4. 파일 내용 해시로 기존 파일과 달라졌는지 확인하고, 헤더 아래의 비어 있지 않은 모든 행을 비교합니다. 서식만 있는 빈 행은 데이터 건수에서 제외합니다. 검증하는 중 파일이 바뀌면 결과를 확정하지 않습니다.

수정 시간만 바뀌고 내용이 같은 파일은 새 결과로 인정하지 않습니다. CSV/XLSX를 이 PC에서 직접 읽으며 Excel·COM·매크로를 실행하지 않습니다. 셀 내용 전체 대신 건수·일치/불일치 수·파일 해시를 반환합니다.

**파일 내용 확인과 업무 성공은 다릅니다.** 이 도구만으로는 `task_verified`가 `true`가 되지 않습니다. 화면의 조건 필드와 파일의 열 이름이 무엇에 대응하는지, 이번 조회가 완료됐는지도 함께 확인해야 합니다.

읽기 제한은 파일 64MiB, XLSX 내부 XML 한 개 128MiB·압축 해제 합계 256MiB, 최대 100,000행·5,000,000셀입니다. 준비 시 지정 폴더는 최대 2,000개 항목, 기준 파일 합계는 256MiB이며 확인 번호는 현재 세션에서 10분간 유효합니다. 수식으로 계산한 검증 열, 외부 링크, 잘못된 XML 등은 확인하지 않습니다. 한도를 넘으면 부분 데이터로 성공 처리하지 않고 이유를 알립니다.

현재 버전의 시험 범위와 한계는 [검증 보고서](VALIDATION.html)를 확인하세요. 아래 항목들은 **이전 버전의 구현·검증 기록**입니다.

## 0.11.1 당시: 선택 창 표시와 연결 진단 보완

UIA 모드는 직접 요소 선택 창을 지원합니다. 창이 보이지 않을 때 F8을 반복하지 말고 `computer_status`의 `version`과 `teaching_support`를 확인하세요. 연결된 실행 폴더와 도우미 파일 존재를 확인할 수 있습니다. 파일 존재는 실행 성공을 뜻하지 않습니다.

최소화·화면 밖·다른 가상 데스크톱의 창을 표시 완료로 판단하지 않도록 보완했습니다. 시작 중 일시적으로 보이지 않는 경우에는 제한 시간 안에서 확인하고, 시작 오류의 단계와 Windows 오류 번호를 보존합니다. 선택은 **3초 후 위치 선택** 버튼으로 시작할 수 있으며 F8은 보조 수단입니다. 요소 정보가 없는 경우에는 실제 오류에 맞춰 프로세스 이미지 선택을 안내합니다.

운영 PC의 실제 원인은 버전과 오류 코드 확인 전에는 확정하지 않습니다. `computer_elements` 목록 조회나 `computer_save_task`는 직접 학습의 대체 기능이 아닙니다.

## 0.11.0: 이미지 선택과 동작 녹화

프로세스 편집 창에서 **이미지로 선택** 또는 **동작 녹화**를 사용할 수 있습니다. Windows가 버튼 정보를 제공하지 않거나 선택한 요소와 Driver 결과를 연결하지 못하면 이미지 선택으로 이어집니다. 프로그램 연결·권한 확인 실패 또는 취소를 이미지 방식으로 건너뛰지는 않습니다.

- 이미지로 쓸 영역을 드래그하고, 미리보기에서 실제 클릭 위치를 지정한 뒤 확인합니다. 같은 모양의 버튼이 여러 개면 주변 이름도 포함하세요.
- 실행할 때마다 현재 창의 캡처에서 저장한 이미지를 다시 찾습니다. 같은 후보가 여러 개이거나 충분히 일치하지 않으면 클릭하지 않습니다.
- **동작 녹화**를 누르고 녹화 창에서 시작한 다음, 연결한 프로그램을 직접 조작합니다. 완료 후 초안의 단계·입력 내용을 확인하고 저장합니다.
- 확인할 수 없는 문자 입력은 직접 지정하거나 삭제해야 저장할 수 있습니다. 비밀번호와 다른 프로그램의 동작을 전역 키 입력 기록으로 수집하지 않습니다.
- 자동으로 잡힌 입력칸 이미지에 바뀌는 글자가 들어 있다면, 단계 미리보기의 **이미지 대상 다시 선택**에서 변하지 않는 고유한 주변 이름과 빈 영역을 선택하세요.
- 이미지 동작 뒤에는 기본적으로 화면 확인 단계를 함께 넣습니다. 0.14.0에서는 완료 요소와 예상 값을 지정해 자동으로 변화를 확인할 수도 있습니다. 실행 결과를 사용자가 확인한 뒤 계속하며, 이미지 위치를 찾았다는 것만으로 업무 완료라고 판단하지 않습니다.

이미지 검색과 녹화 처리는 이 PC에서 수행하며 외부 API나 모델을 호출하지 않습니다. 프로세스 파일에는 직접 선택한 이미지와 지정한 입력 내용이 저장됩니다. 당시 버전에서는 실행 중 확인 이미지를 연결한 MCP 클라이언트에 전달했습니다. 0.15.0의 기본 연결은 이 PC의 화면 확인 창을 사용하며, 모델로의 이미지 전달은 명시적으로 요청하고 전달 시험을 통과한 연결에서만 사용합니다. 전체 동영상을 저장하는 녹화나 모든 앱·드래그·보호된 입력을 완벽하게 재현하는 기능은 아닙니다.

`computer_teach_element`는 UIA 요소 학습용입니다. 이미지 선택과 녹화는 `computer_process_editor`의 프로세스 단계로 저장합니다. 실행 중 알려진 Win32 Edit 비밀번호 입력칸은 문자·키 입력을 차단하지만, 모든 앱의 자체 비밀번호 칸까지 판별하지는 않습니다.

사용 순서는 [프로세스 작성 안내](PROCESS_GUIDE.html)를 참고하세요. 최종 검증 결과와 한계는 [검증 보고서](VALIDATION.html)에 있습니다.

## 0.10.0 당시: 프로세스 편집 창

채팅에서 **“지금 열린 프로그램으로 반복 작업을 만들고 싶어. 프로세스 편집 창을 열어줘. 요소는 내가 직접 선택할게.”**라고 요청하세요.

1. 프로그램을 고르고 **요소 직접 선택**으로 원하는 요소를 확인합니다.
2. 클릭·입력·키보드·선택 동작을 고릅니다. 클릭·키보드는 결과를 확인할 요소와 예상값도 지정합니다.
3. 요소가 나타날 때까지 대기, 고정 시간 대기, 화면 이미지 확인을 필요한 위치에 추가합니다.
4. 목록에서 프로그램·요소·동작·입력값·확인 조건을 보고, 순서를 바꾸거나 잘못된 단계를 삭제합니다.
5. 이름을 붙여 저장한 뒤 **“저장한 ○○ 프로세스를 실행해줘”**라고 요청합니다. 화면 확인 단계는 이미지를 보여주고 잠시 멈추며, 사용자가 확인한 뒤 이어갑니다.

작성 중에는 업무 프로그램을 조작하지 않습니다. 다음 화면은 사용자가 직접 이동한 뒤 선택합니다. 모든 마우스 움직임을 자동 녹화하는 방식은 아닙니다. 저장한 프로세스를 다시 열면 새 복사본으로 저장하며 원본을 보존합니다. 직접 작성한 입력값과 직접 선택한 이미지 대상은 작업 파일에 저장됩니다. 실행 중 확인 이미지는 작업 정의에 저장하지 않습니다. 1~30단계, 대기는 단계마다 최대 60초입니다.

**[초보자용 프로세스 만들기 안내](PROCESS_GUIDE.html)** · `computer_process_editor` / `computer_process_status` / `computer_run_task`

요소 저장 전 대조에서 Driver의 `frame{x,y,w,h}` 형식을 처리하도록 수정했습니다. 자동화 ID가 누락된 경우에도 정확한 이름·종류·위치가 모두 맞는 요소만 교차 확인합니다. 명시적으로 다른 ID나 여러 후보를 임의로 받아들이지는 않습니다.

**자체 그림 화면의 버튼이 Windows 접근성 정보에 아예 없는 경우에는 UIA 학습을 할 수 없습니다.** 실제 로컬 프로그램에서 네이티브 UIA와 Driver에 버튼 정보가 없는 경우를 확인했습니다. 이때 `picker_controls_not_exposed`로 이유를 알리고 F8 반복이나 상위 영역을 버튼으로 잘못 저장하는 일을 막습니다. 0.10.0에는 그림 버튼의 이미지 학습·자동 재탐색이 없었습니다. 현재 버전에서는 위의 **이미지로 선택** 기능을 사용할 수 있습니다.

새 ZIP 전체를 압축 풀고 기존 설정을 유지한 채 연결을 갱신한 뒤 **0.14.0** 및 `computer_process_editor`가 표시되는지 확인하세요. 편집 실행파일은 MCP가 자동 실행합니다.

## 0.9.0: 직접 선택 → 확인 → 학습 완료

1. 채팅에서 **“이 화면의 신청 상태를 직접 가르쳐줄게. 요소 학습을 시작해줘.”**라고 요청합니다.
2. 선택 창이 실제로 나타나면 **3초 후 위치 선택**을 누르고 원하는 요소 위로 마우스를 옮깁니다. 마우스를 올리고 **F8**을 눌러도 됩니다. 업무 버튼은 클릭하지 않습니다.
3. 선택 창에서 **요소 이름·종류**를 확인합니다. 버튼 안의 글자가 잡혔다면 목록에서 실제 상위 버튼을 직접 고릅니다. 잘못 골랐다면 다시 선택합니다.
4. **이 요소로 선택**을 누르면 MCP가 현재 화면과 대조해 저장합니다. 채팅에서 **학습 완료**가 확인돼야 저장된 것입니다.
5. **“배운 신청 상태를 신청으로 바꾸고 결과를 확인해줘.”**라고 요청합니다.

선택 창의 표시를 확인한 뒤 안내합니다. 창이 안 뜨는데 F8 안내만 반복하지 않으며, 대기 중 같은 요청은 기존 학습을 이어갑니다. Esc·취소 또는 채팅에서 취소할 수 있습니다. 창 표시 실패·요소 응답 지연·중복 요소·저장 실패를 구분하고 자동 재시도하지 않습니다. 학습 중에는 다른 화면 작업을 잠시 멈춥니다.

**UIA는 직접 학습을 지원하는 기본 방식입니다.** 프로그램이 요소 정보를 제공하지 않거나 고유한 기준을 만들 수 없는 화면은 학습 성공으로 표시하지 않습니다. `computer_elements`는 목록 조회, `computer_save_task`는 작업 저장이며 직접 요소 선택의 대체 기능이 아닙니다.

이름·화면 분류·설명·찾는 기준을 이 PC에 저장합니다. LLM 자체 훈련이나 전체 작업 녹화는 아닙니다. 입력 값·이미지·좌표·임시 창 번호는 학습 파일에 저장하지 않습니다. “배운 요소 목록을 보여줘”, “조회 버튼을 다시 가르칠게”, “저장한 조회 버튼을 지워줘”로 관리합니다. 같은 이름의 대상은 고유한 상위 영역으로 구분하며 화면이 바뀌면 다시 확인합니다.

새 배포 ZIP을 모두 압축 풀고 `INSTALL.md`를 첨부하여 **“기존 Driver·프로그램·저장한 작업·학습 요소를 유지하고 이 버전으로 연결을 갱신해줘”**라고 요청하세요. 연결을 다시 연 뒤 **0.14.0**과 `computer_teach_status`가 표시돼야 새 방식이 적용됩니다. 기존 연결 파일을 그대로 실행하면 이전 버전이 계속 사용됩니다.

## 0.8.0: 프로그램 시작 방식 수정

이전에는 프로그램을 MCP 임시 기록 폴더에서 시작했습니다. 이제 EXE가 있는 폴더에서 시작하고, 동봉 Python/Tcl 환경 변수가 업무 프로그램에 전달되지 않도록 정리합니다. 창이 표시됐는지와 요청한 프로세스의 조기 종료를 확인하며, 런처가 종료되고 다른 창이 열린 경우에는 정상 인계로 단정하지 않습니다. 불확실한 실행을 자동 반복하지 않습니다.

`NullReferenceException`이 종료 처리 함수에서 나왔다는 로그만으로 최초 실행 실패 원인을 확정할 수는 없습니다. 이 변경은 작업 폴더·환경 변수 차이를 보완하며, 관리자 실행 여부는 MCP의 현재 권한을 그대로 따릅니다. 해당 운영 프로그램의 실제 정상 실행은 운영 PC에서 다시 확인해야 합니다.

0.7.1은 설치 연결 진단을 수정합니다. 0.7.0에서 Job 객체를 만들지 못하면 연결 검사 전에 중단하던 조건을 보완하고, 실제 시작 오류·종료 코드·UAC 취소를 구분합니다. Job을 사용할 수 없어도 읽기 전용 연결과 정상 종료를 따로 확인하며, 종료 확인 실패는 설치 성공으로 처리하지 않습니다. 이 오류 메시지만으로 회사 보안 정책 차단을 단정하지 않습니다.

자동 검사 485개 중 483개 통과, 2개 조건부 제외. 새 배포 구성과 기존 Driver로 Job 실패를 주입한 일반 실행 상태 조회에서 32개 도구·Driver 스키마·정상 종료를 확인했습니다. 실제 운영 PC의 실패 원인과 관리자 화면 조작은 별도 검증이 필요합니다.

0.7.0부터 MCP와 Cua Driver를 관리자 권한으로 실행하는 전용 연결 프로그램을 사용합니다. 일반 Claude Code에서도 연결할 수 있으며 Windows UAC 승인이 필요할 수 있습니다. 같은 로그인 사용자·세션만 허용하며 취소·차단·다른 계정 사용 시 일반 실행으로 대신 연결하지 않습니다. `computer_status.execution`에서 실제 관리자·승격·무결성 수준을 확인합니다.

관리자 권한을 확보해도 다른 계정의 프로그램, Windows 보안 확인 화면, 회사 정책으로 차단된 프로그램, UIA를 제공하지 않는 화면까지 자동 지원되는 것은 아닙니다. 기존 허용 프로그램과 작업 제한은 유지합니다.

일반 권한의 전용 연결 경로에서는 합성 시험 앱의 한글 입력·버튼 결과·실제 프로세스 종료를 확인했습니다. 이 PC의 관리자 실행 시험은 승인 응답을 받지 못해 연결 시간이 초과됐으며, 관리자 상태의 실제 화면 조작은 아직 확인하지 못했습니다. 원래 0.6.0의 종료 시험 기록은 `VALIDATION.html`에 보존했습니다.
