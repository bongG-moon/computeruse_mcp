# Computer Use MCP 0.16.0

Windows 프로그램을 채팅으로 조작하거나, 직접 작업을 녹화해 반복 실행하는 로컬 MCP입니다. 두 방식이 같은 창 확인·요소/이미지 선택·입력·결과 확인 엔진을 사용합니다.

> **0.16.0의 실제 앱 조작과 저장 작업 재생 검증을 완료했습니다.** 배포 파일과 공개 상태는 [0.16.0 Release 안내](https://github.com/bongG-moon/computeruse_mcp/releases/tag/v0.16.0), 구체적인 시험 범위는 [검증 기록](VALIDATION.html#validation-0160)을 확인하세요.

현재 MuMu의 첫 번째 줄 실행 버튼을 한 번 누른 뒤 로딩 표시와 녹색 실행 상태로 바뀐 화면을 확인했습니다. Android 내부의 준비 완료는 확인하지 않았습니다. 메모장은 입력한 문구의 정확한 일치와 창 종료를 확인했습니다.

Chrome 시험 페이지에서 검색어 입력·신청 상태 선택·조회 결과 일치와 종료를 확인했습니다. 계산기는 2 + 3 = 5와 종료, Microsoft Store는 앱 항목 선택과 종료를 확인했습니다. 계산기의 중간 수식은 모델의 화면 확인을 사용했고, Store 종료는 첫 응답이 불명확해 입력을 반복하지 않고 읽기 전용으로 다시 확인했습니다.

시험 앱에서는 실제 동작 3개를 5단계로 기록·저장하고, 중단된 실행의 재개와 처음부터 새로 실행하는 시험을 모두 완료했습니다. 완료한 동작을 중복하지 않았으며 화면 확인 2개는 모델의 시각 판단으로 구분했습니다. MuMu에서는 원래 녹화 중 빠진 한 단계의 대상을 사용자가 편집창에서 다시 지정한 뒤 작업을 저장했습니다. 이후 중단 지점부터 이어가기와 처음부터 새로 실행하기가 모두 **4/4단계 완료**됐습니다. 저장된 버튼과 현재 버튼의 색상 차이는 모델이 현재 화면에서 같은 대상을 확인해 복구했고, 추가로 가르치거나 저장한 작업을 바꾸지 않았습니다. 이어가기에서 이미 완료한 첫 클릭도 반복하지 않았습니다. 각 실행의 화면 확인 2개는 모델 판단인 `visual_assessed`입니다. 최신 네이티브 캡처 변경은 자동 검사와 시험 앱에서 확인했으며, MuMu의 원래 녹화를 최신 버전으로 전부 다시 녹화한 것은 아닙니다. 전체 검사는 1,327개 중 1,325개 통과·2개 조건부 제외(69.477초), 별도 독립 검사는 191개 모두 통과했습니다.

## 두 가지 사용 방법

**말로 요청하기**

> 계산기를 열고 12 + 30을 계산한 뒤 결과를 확인해줘.

> 지금 열린 프로그램을 등록하고, 첫 번째 줄의 실행 버튼을 눌러줘.

MCP가 현재 창을 연결합니다. 버튼 정보를 읽을 수 있으면 요소를 사용하고, 그림으로만 표시되는 화면은 이미지 이해가 가능한 연결 모델이 현재 이미지를 보고 대상을 지정합니다. 등록하지 않은 앱이나 여러 개의 구별되지 않는 창을 임의로 고르지 않습니다.

**직접 가르치기**

> 이 프로그램에서 반복할 작업을 녹화할 수 있게 프로세스 편집창을 열어줘.

1. **동작 녹화**를 시작하고 평소처럼 클릭·입력합니다. 실제 앱에 동작이 적용됩니다.
2. 기록을 마치고 단계의 대상·동작·값·완료 기준을 확인합니다.
3. 대상이 잘못 잡혔다면 **화면에서 선택** 한 곳에서 다시 지정합니다. 요소와 이미지 방식을 사용자가 미리 고를 필요가 없습니다.
4. **시험 실행**으로 결과를 확인하고 프로세스를 저장합니다.
5. 다음부터 “저장한 작업을 실행해줘”라고 요청합니다.

## 다시 녹화하지 않고 바꾸기

> 저장한 작업에서 검색어를 입력 변수로 만들고 기본값을 W로 해줘.

> 오늘은 검색어를 N으로 실행해줘. 원래 저장한 기본값은 유지해줘.

> 이 단계의 대기 시간을 2초로 바꾸고, 이전 버전도 남겨줘.

입력값은 문자·숫자·선택값·날짜·목록으로 정의할 수 있습니다. 단계에는 고유 ID가 있고 수정 충돌을 검사합니다. 실행을 중간부터 이어갈 때는 그 실행이 시작한 버전과 입력값을 그대로 사용합니다. 스킬 내보내기는 저장된 프로세스를 호출하는 작은 `SKILL.md`를 만들며, 사용자 프로필에 자동 설치하지 않습니다.

대상을 직접 고쳐 관련 단계의 문제가 모두 해소되면 그 문제에 해당하는 경고도 해제됩니다. 동작 누락이나 입력값 미확인처럼 별개의 경고는 남으며, 저장할 때 실제로 남은 검토 사항을 확인할 수 있습니다.

저장된 버튼의 색상·상태가 달라 이미지 재생이 **입력 전에** 멈춘 경우, 이미지 전달을 허용한 연결 모델이 저장된 대상과 현재 화면을 함께 보고 같은 대상을 다시 지정할 수 있습니다. 이 선택은 같은 실행의 해당 단계에서 한 번만 사용하고 저장한 작업은 그대로 유지합니다. 이미 전달됐거나 전달 여부가 불명확한 입력에는 적용하지 않습니다.

현재 이 복구 경로는 앞선 단계의 값·상태 조건을 다시 읽습니다. 같은 창에서 모델이 확인한 결과는 화면 전체가 그대로일 때만 재사용하므로 시계·커서·애니메이션이 계속 바뀌는 창에서는 다시 관찰해야 할 수 있습니다. 앞선 화면 확인이 다른 창에서 이루어졌다면 현재 창의 그림으로 대신 인정하지 않고 자동 이어가기를 멈춥니다.

## 연결과 프로그램 등록

배포 ZIP 전체를 새 폴더에 풀고 [INSTALL.md](INSTALL.md)를 채팅에 첨부하세요. Python 설치나 JSON 편집은 필요하지 않습니다. 기존 사용자 설정과 저장한 작업은 유지합니다. 사용 중인 연결을 갱신한 뒤 `computer_status.version`을 확인합니다.

메모장·계산기·Chrome·Microsoft Store는 설치된 실행 경로를 찾아 등록할 수 있습니다. 다른 프로그램도 열린 창을 고르거나 EXE·실행 인자·업무 주소를 알려주면 등록할 수 있습니다. 특정 사내 프로그램 이름을 제품에 고정하지 않습니다.

## 도구 구성

| 목적 | 도구 |
| --- | --- |
| 프로그램 목록·추가 | `computer_programs`, `computer_register_program` |
| 창 열기·관찰·동작 | `computer_open`, `computer_observe`, `computer_act` |
| 녹화·요소 선택·편집·시험 | `computer_process_editor` |
| 저장 작업 조회·수정·실행·스킬 | `computer_tasks`, `computer_update_task`, `computer_run_task`, `computer_export_skill` |
| 상태·긴급 중지 | `computer_status`, `computer_stop` |

기본 제공 도구는 12개입니다. 이전 도구가 필요한 기존 클라이언트는 설정의 `tool_profile: legacy`로 호환 모드를 사용할 수 있습니다. 일반 사용 흐름에는 이 설정이 필요하지 않습니다.

## 결과와 한계

입력을 보냈다는 응답만으로 성공 처리하지 않습니다. 읽은 값으로 확인한 결과와 모델이 화면으로 판단한 결과(`visual_assessed`)를 구분합니다. 화면이 바뀌거나 대상이 모호하면 다시 관찰하고, 이미 전달했을 수 있는 입력은 자동 반복하지 않습니다. 녹화의 누락 경고와 기존 사람 확인 단계도 보존합니다.

화면을 해석하는 LLM은 연결한 앱에서 제공합니다. 이 MCP 자체는 외부 모델 API를 호출하지 않습니다. 기본은 텍스트 전달이며, 이미지 지원과 화면 사용이 확인된 연결은 `computer_open(image_delivery="vision")`으로 이미지 전달을 켤 수 있습니다. 연결 모델이 외부 서비스라면 화면도 그 서비스로 전달되므로 사내망만 사용하려면 클라이언트와 모델도 사내 환경이어야 합니다.

종료 요청 시 실제 창/프로세스 종료와 남은 저장 대화상자를 확인합니다. 세션 중지는 업무 앱 종료가 아닙니다. 사용자 문서의 저장·폐기 선택을 추측하거나 강제 종료하지 않습니다.
