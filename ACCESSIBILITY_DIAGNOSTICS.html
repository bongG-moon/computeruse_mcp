왜 요소가 빠졌는지 확인하고, 같은 행을 다시 찾기

0.19.1 이후 개발 소스에 추가한 기능입니다. 설치된 0.19.1 Release에 자동 반영되지 않습니다. 진단은 읽기 전용이며 기존 녹화·이미지·revision을 수정하지 않습니다.

사용 방법

  1. 평소처럼 대상 프로그램을 연결하고 프로세스 편집창을 엽니다.
  2. 대상 창을 선택한 뒤 요소 진단 · 이 PC에만 저장을 누릅니다.
  3. 진단 미리보기에서 Provider / Driver / MCP 정보를 각각 확인합니다. 큰 보고서는 미리보기만 제한하며 전체 JSON은 표시된 로컬 경로에 있습니다.
  4. 목록 열기 전·후, 속성 편집 중, 하위 메뉴가 새로 열렸을 때 각각 관찰합니다. 진단 자체는 창을 활성화하거나 입력하지 않습니다. 편집창 버튼을 클릭하면 앱의 일시 팝업이 닫힐 수 있으므로 열린 팝업은 기존에 연결한 창 참조로 읽기 전용 진단을 요청합니다.

채팅 연결에서는 computer_observe(window_ref=현재 참조, diagnostics=true)를 사용합니다. legacy 구성은 computer_inspect(pid, window_id, diagnostics=true)입니다. 진단 옵션과 이미지·검색 옵션은 함께 지정하지 않습니다.

data_policy=local에서는 상세 정보·업무 값·파일 경로를 채팅에 보내지 않고 진단 ID만 반환합니다. 상세 JSON은 실행별 폴더의 accessibility-diagnostics/에 남으며, 종료된 실행의 파일은 7일 뒤 자동 정리 대상입니다. 명시적인 connected 구성은 해당 연결에 보고서를 반환합니다. 별도 모델 API·원격 수집·자동 업로드는 없습니다.

표 기반 콤보·동적 편집기

ComboBox 내부의 실제 Row/DataItem이 select 기능과 현재 선택 상태를 제공하면 일반 ListItem과 함께 처리할 수 있습니다. 다중 체크 목록은 단일 값 선택으로 취급하지 않습니다. Searchable 검색 모달, 일반 드롭다운, 속성 편집기는 각각 새 창/요소로 관찰해야 합니다.

Custom/DataItem/Cell 등 입력기는 Value supported, read_only=false, set_value 동작이 실제 Driver 관찰에 함께 있을 때만 입력을 허용합니다. 타입 이름이나 정적 WinForms 필드명만으로 입력 가능성을 추정하지 않습니다. 패턴 지원과 실제 실행 성공은 별도입니다.

반복 행을 지정하는 방법

같은 이름의 셀이 많을 때 행 번호나 첫 후보를 누르지 않고, 현재 표의 고유 행 값과 열 요소를 결합합니다. 아래 이름과 값은 설명용이며 실제 관찰값으로 지정합니다.

{
  "name": "Family",
  "within": {"automation_id": "ObservedGrid"},
  "row": {
    "key": {"name": "Device"},
    "property": "value",
    "equals": "DEVICE-001"
  }
}

고유한 표 범위, 실제 행 계층, 유일한 행 키, 유일한 대상 열이 모두 필요합니다. 중복 키·중복 열·잘린 관찰·없는 계층은 입력 전에 거부합니다. 화면 밖 셀을 좌표로 추측하거나 진단 노드를 입력 대상으로 승격하지 않습니다.

현재 Driver의 공개 입력 계약에는 Grid.GetItem / Realize / ScrollItem 전용 호출이 없습니다. 해당 패턴은 진단에서 확인하되 자동 실행을 지원한다고 표시하지 않습니다. 기존에 승인된 스크롤 후 새 관찰을 얻어 행 키를 다시 찾습니다.

속도와 검증 범위

진단은 요청할 때만 실행됩니다. 평소 observe/녹화/재생에는 UIA 3 view나 MSAA 전체 읽기를 추가하지 않습니다. 소스별 읽기에는 시간·깊이·개수 제한이 있으며 중단된 소스가 다른 소스 결과를 지우지 않습니다.

시험 앱과 합성 관찰의 검증은 사내 벤더 DLL의 실제 동작을 보장하지 않습니다. 100/125/150% 크기로 만든 fixture와 실제 Windows DPI·멀티모니터 검증은 구분해야 합니다. 운영 선택 10회, 팝업 연결, 최종 내보내기 파일 내용은 실제 앱에서 별도로 확인해야 합니다.

공식 동작 근거: UIA view 탐색, MSAA child ID와 IDispatch, 가상화된 항목.
