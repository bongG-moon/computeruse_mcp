# 혼합 Windows 업무 화면 관찰 전략

정적 분석에서 얻은 구조를 일반화한 관찰 지침이다. 내부 소스, 메서드, 사내 화면과 분석 원문은 배포하지 않는다. 아래 지침은 Provider가 실제 반환한 노드만 해석하는 데 사용한다.

`observe.py`는 계속 읽기 전용이다. 0.2.0의 `interact.py`로 사용자가 요청한 조작을 수행할 때는 [조작 절차](actions.md)를 함께 적용한다. 아래의 수동 화면 준비 설명은 관찰 모드 기준이며 조작 모드 전체를 금지하는 규칙이 아니다.

| 화면 | 관찰할 근거 | 남겨야 할 한계 |
|---|---|---|
| WPF 호스트 안의 WinForms 업무 화면 | 현재 탭, WindowsFormsHost/ElementHost 경계, 업무 Form과 툴바를 구분 | 시작 창이 실제 업무 창과 같다는 가정 금지 |
| FxMenuAgent의 독립 업무 창 | 명시한 업무 HWND와 PID, 같은 프로세스의 별도 검색/편집 창 | owner가 없는 업무 창도 있을 수 있다. 동일 PID는 관계 증거가 아니다 |
| 자식을 노출하지 않는 메뉴 peer | 부모 트리와 명시한 메뉴 HWND를 각각 읽음 | GetChildren가 빈 Provider는 깊이를 늘려도 복구되지 않는다. OCR/MSAA를 구현했다고 표현하지 않음 |
| 다열 콤보 | 열린 목록의 열 제목, 코드, 표시 이름, 현재 선택 항목 | 표시 문자열과 내부 값의 동등성은 관찰 근거가 있어야 한다 |
| 별도 검색 모달 | 사용자가 명시한 검색 창과 원래 콤보 범위를 별도 저장 | 검색 결과와 원래 콤보의 반영 값은 서로 다른 관찰이다 |
| 동적 셀 편집기 | 원래 표/열/행 업무 키와 현재 편집기, 체크된 항목 집합 | 편집기 객체와 HWND가 재생성될 수 있다. 목록 인덱스를 고정하지 않음 |
| PropertyGrid | 범주, 속성 이름, 선택한 업무 행과 동적 드롭다운 | 같은 이름을 범주로 구분. 편집기 닫힘과 업무 저장 완료는 다름 |
| FarPoint/Infragistics 계열 표 | 현재 시트, 머리글, 관찰된 행 키, 선택 범위와 스크롤 | 셀이 각각 HWND라는 가정 금지. UIA의 row 역할만으로 셀 주소 접근을 보장하지 않음 |
| 재생성되는 메뉴 | 현재 부모 메뉴, 새 자식 경로, enabled 상태 | 과거 ref/인덱스 재사용 금지. 팝업과 부모 scope를 합쳐 중복을 숨기지 않음 |

## 메뉴

이미 열린 부모 메뉴와 하위 메뉴를 읽는다. `Export to excel`, `Active sheet`, `All sheet`처럼 공개 라이브러리에서 쓰는 명령은 서로 다른 항목으로 구분한다. 하위 메뉴가 별도 HWND일 수도, 부모 트리의 논리 자식일 수도 있다. 트리 경로를 보존하고 중복 이름에는 조상 문맥을 붙인다. 임의 좌표나 색만으로 항목을 확정하지 않는다. 원본 `--surface menu`는 같은 PID 전체를 탐색하므로 이 래퍼에서 차단한다. 지정 HWND와 부모 트리에 보이지 않는 메뉴는 미관찰이며 다른 창의 메뉴로 보충하지 않는다.

## 콤보와 속성

표시 이름, 코드/값, 선택 상태는 별개 필드로 보존한다. 코드가 노출되지 않으면 추정해 채우지 않는다. 다중 체크는 선택 집합으로 읽고 줄 번호나 클릭 횟수로 변환하지 않는다. 사용자가 편집기를 열거나 닫은 뒤에는 현재 화면을 새로 읽는다. 값이 바뀌었다는 사실을 저장 성공으로 확장하지 않는다.

## 표와 완료 상태

동일 Form에 표가 여러 개면 각 조상 경로와 머리글, 용도를 확인한다. 정렬, 필터, 열 재배치 후 과거 인덱스는 식별자가 아니다. sheet 전체와 selected ranges를 구분하고, `Active sheet`라는 메뉴 이름만으로 시트 전체 출력이라고 단정하지 않는다.

표가 보이는 상태에서도 이전 조회 결과가 남아 있을 수 있다. 이번 조회의 busy 해제, 요청/완료 표식 또는 결과 세대가 관찰되지 않으면 완료는 미확인이다. 성공, 빈 결과, 진행 중, 오류를 구분한다. 메뉴 닫힘은 파일이나 Workbook 생성 증거가 아니다.

## 근거 수준

원시 트리는 현재 Provider의 관찰이다. 역할 기반 후보는 분류 힌트이며 정확한 업무 대상 확정이 아니다. class/native_id가 없으면 정적 필드명을 대신 쓰지 않는다. patterns 필드가 없다는 이유로 패턴 미지원이라고 쓰지 않는다. 빈 peer의 원인도 런타임 정보 없이 단정하지 않는다.

합성 WinForms/WPF 테스트는 래퍼의 범위와 정보 보존을 검증한다. 실제 FX, 사내 Infragistics/FarPoint 배포 버전, DPI별 인식 개선을 증명하지 않는다.
