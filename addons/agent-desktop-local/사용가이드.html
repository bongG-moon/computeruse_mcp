릴리스에서 Agent-Desktop-Local-0.1.1-windows-x64.zip을 받으세요. source.zip이나 GitHub의 Source code는 개발 소스이므로 이 안내의 실행용 파일이 아닙니다.

구분기존 Computer Use MCP이번 Agent Desktop Local

2

ZIP 전체를 로컬 폴더에 풀어 주세요

파일 탐색기에서 ZIP을 오른쪽 클릭한 뒤 모두 압축 풀기를 선택합니다. 회사에서 허용한, 본인이 쓸 수 있는 동기화되지 않는 로컬 디스크 폴더를 고르세요. 기존 CUA 폴더에 덮어쓰지 않습니다.

압축을 푼 agent-desktop-local 폴더 안에 아래 항목이 함께 있어야 합니다. ZIP 내부에서 직접 실행하거나 EXE만 따로 옮기지 마세요.

agent-desktop-local
├─ SKILL.md
├─ 사용가이드.html       ← 지금 보고 있는 안내
├─ bin
│  └─ agent-desktop.exe
└─ scripts
   └─ observe.py
OneDrive, 클라우드 동기화 폴더와 공유 드라이브는 결과 보관 위치로 사용하지 마세요. 이 도구는 네트워크 경로를 거부하지만, 로컬 폴더의 동기화 여부까지 알아내지는 못합니다.
3

사내 에이전트가 있다면 이렇게 요청하세요

가장 쉬운 방법은 승인된 사내 에이전트에게 SKILL.md의 전체 경로를 알려 주는 것입니다. 파일 탐색기에서 해당 파일을 Shift + 오른쪽 클릭 → 경로로 복사하여 확인할 수 있습니다.

“아래 경로의 SKILL.md를 읽고 따라 줘.
D:\LocalTools\agent-desktop-local\SKILL.md

내가 열어 둔 APP.exe의 메뉴, 콤보와 표를 읽기 전용으로 확인해 줘. 실행파일 이름과 현재 창을 먼저 확인하고, 여러 창이 있으면 임의로 고르지 말아 줘. 결과는 이 스킬 폴더 아래 results에 보관해 줘. 기존 CUA 설정은 그대로 유지하고 원시 결과는 승인된 사내 환경 안에서만 해석해 줘.”

위 경로와 APP.exe는 예시입니다. 실제 압축 해제 위치와 대상 이름으로 바꿔 주세요.

모델만 연결한 대화창에서는 실행되지 않습니다. 사내 모델을 쓰는 에이전트에 로컬 파일 읽기와 명령 실행 도구가 있어야 합니다. 그런 도구가 없으면 아래 4~7번을 직접 따라 하면 됩니다. SKILL.md 자체가 모델이나 MCP 서버를 설치하지는 않습니다.
사용자FX를 직접 열기
사내 에이전트SKILL.md 읽기
로컬 래퍼지정한 창 관찰
사내 모델로컬 자료 해석
4

직접 실행하려면 PowerShell을 여세요

  1. 파일 탐색기에서 SKILL.md와 scripts가 보이는 폴더를 엽니다.
  2. 탐색기 위쪽 주소 표시줄을 클릭하고 powershell이라고 입력한 뒤 Enter를 누릅니다. 검색창이 아니라 폴더 경로가 적힌 곳입니다.
  3. 열린 PowerShell에서 아래 명령을 한 번 실행합니다.
python --version

Python 3.10 이상의 버전이 나오면 진행할 수 있습니다. Windows는 10 1809 이상 x64 환경이 필요합니다. 관리자 PowerShell은 열지 마세요.

“python을 찾을 수 없다”거나 설치 화면이 뜨면

자동 설치를 진행하지 말고 회사에서 허용한 기존 python.exe 경로를 확인하세요. 아래처럼 명령 앞부분을 바꿀 수 있습니다. 공백이 있는 전체 경로는 따옴표로 감싸고 앞에 &를 붙입니다.

& "D:\ApprovedPython\python.exe" --version

이 경로도 예시입니다. 이후 모든 명령의 첫 python 부분을 같은 방식으로 바꿉니다. 회사에서 사용할 수 있는 Python이 없으면 준비 단계에서 멈추세요. 보안 정책이나 PATH를 자동 변경할 필요는 없습니다.

이제 결과를 저장할 폴더를 준비합니다. 아래 두 줄을 그대로 실행하세요. 이 작업은 스킬 폴더 안에 results만 만듭니다.

New-Item -ItemType Directory -Force .\results | Out-Null
$outputDir = (Resolve-Path .\results).Path

새 PowerShell 창을 열면 $outputDir 값이 사라지므로 두 줄을 다시 실행하세요. 공유 경로나 쓰기 권한이 없는 폴더라면 회사에서 허용한 로컬 위치로 압축 해제 위치를 바꿉니다.

5

FX의 실행파일과 관찰할 창을 확인하세요

  1. FX를 평소처럼 직접 실행하고 읽으려는 업무 화면을 엽니다. 최소화하지 마세요.
  2. 작업 관리자 → 세부 정보에서 해당 앱의 정확한 .exe 이름을 확인합니다. “관리자 권한으로 실행”은 필요하지 않습니다.
  3. 아래 명령의 APP.exe를 그 이름으로 바꾸고 실행합니다.
python -X utf8 -B .\scripts\observe.py inventory --exe-name "APP.exe" --output "$outputDir"

이 명령은 앱 창 목록만 읽습니다. 화면에는 다음과 같은 짧은 결과가 표시됩니다. 아래 영수증 ID는 설명용 예시입니다.

{"status":"observed","receipt":"0123456789abcdef0123456789abcdef", ...}

탐색기로 results를 열고, 출력된 receipt와 같은 이름의 폴더를 엽니다. 그 안의 inventory.json을 메모장으로 로컬에서 확인하세요.

항목무엇인가요?어디에 쓰나요?
title현재 창 제목읽으려는 업무 창인지 확인
pid실행 중인 프로세스 번호다음 명령의 --pid
hwnd현재 창의 숫자 식별자다음 명령의 --hwnd
같은 앱에 창이 여러 개면 제목과 실제 화면을 대조해 하나를 고릅니다. 창을 닫았다가 다시 열었으면 번호가 바뀔 수 있으므로 목록부터 다시 확인하세요. 원시 JSON을 외부 대화창에 붙여넣지 마세요.
6

창 하나를 읽어 보세요

확인한 실행파일 이름, pid, hwnd를 아래 명령에 넣습니다. 1234와 5678은 예시 숫자이므로 그대로 실행하지 마세요.

python -X utf8 -B .\scripts\observe.py observe --exe-name "APP.exe" --pid 1234 --hwnd 5678 --stage grid --output "$outputDir"
읽을 내용--stage 뒤에 쓸 값
창 전체window
메뉴menu
콤보와 선택 목록combo
표grid
속성 편집기property

stage는 결과를 어떤 종류로 해석할지 지정합니다. 모두 지정한 창만 읽으며 메뉴를 열거나 콤보를 펼치거나 표를 스크롤하지 않습니다.

PowerShell로 돌아오면 콤보나 메뉴가 닫히는 경우

명령을 먼저 준비하고, 아래처럼 8초 대기 후 관찰하도록 실행하세요. Enter를 누른 뒤 8초 안에 FX로 돌아가 원하는 메뉴나 콤보를 직접 엽니다. 관찰 중에는 다른 창으로 전환하지 마세요.

Start-Sleep -Seconds 8
python -X utf8 -B .\scripts\observe.py observe --exe-name "APP.exe" --pid 1234 --hwnd 5678 --stage combo --output "$outputDir"

이 예시도 이름과 숫자를 바꿉니다. 기본 창 하나를 읽는 경우 명령 시작 후 약 40초 정도 기다린 뒤 PowerShell에서 결과를 확인하면 진행 중에 창을 바꿀 가능성을 줄일 수 있습니다. 부모나 관련 창을 추가하면 시간이 더 걸릴 수 있습니다. 화면을 바꾼 결과가 interrupted이면 유효한 관찰로 취급하지 않습니다.

예전에 본 HWND를 다른 창에 재사용하거나, 조회/저장/내보내기 버튼을 자동 클릭하도록 요청하지 마세요. 이 스킬은 열린 화면의 인식 상태를 검토하는 용도입니다.
7

로컬 결과에서 읽힌 내용을 확인하세요

관찰 명령이 반환한 새 receipt 폴더를 엽니다. 창 목록을 읽었을 때와 관찰했을 때의 영수증 폴더는 서로 다릅니다.

파일확인할 내용
receipt.json상태, 개수와 전경 유지 여부
observation.json관찰한 창 범위와 각 범위의 상태
target-window.json원시 트리와 recognition의 이름, 값, 선택 상태, 계층
inventory.json이 관찰에서 대상으로 확인한 창

관찰되지 않은 범위의 target-window.json은 생기지 않을 수 있습니다. 결과 폴더의 다른 상태 파일에도 업무 내용이 남을 수 있으므로 폴더 전체를 사내 업무 자료로 취급하세요.

사내 모델에는 “이 로컬 결과의 이름, 표시값과 선택 상태를 구분하고, 실제로 읽힌 근거만 정리해 줘”라고 요청할 수 있습니다. 코드값과 표시 문자열이 항상 같은 것은 아닙니다.

상태뜻과 다음 행동
observed접근성 트리를 읽었습니다. 원하는 업무 항목을 정확히 인식했거나 업무가 완료됐다는 뜻은 아닙니다.
partial일부 창 범위만 읽었습니다. 실패한 범위를 확인하고 전체 성공으로 합치지 않습니다.
no_matching_window목록에서 일치하는 창이 없습니다. 앱 실행 상태와 정확한 실행파일 이름을 확인합니다.
unavailable대상 범위를 읽지 못했습니다. 없는 요소나 메뉴를 추측해서 채우지 않습니다.
blocked대상 식별, 경로, 바이너리 또는 실행 조건을 확인하지 못했습니다. 인수와 준비 상태부터 확인하고 보안 차단을 우회하지 않습니다.
interrupted관찰 전후에 전경 창이 달라졌습니다. 기록은 남을 수 있지만 이 관찰은 유효한 결과로 사용하지 않습니다.

멈추려면 PowerShell에서 Ctrl+C를 누를 수 있습니다. 중단 뒤에는 대상 상태를 다시 확인하세요. 같은 명령을 무작정 반복하거나 실패를 해결하려고 보안 설정을 낮추지 않습니다.

8

팝업은 부모 창과 구분해서 읽습니다

콤보의 떠 있는 목록이나 속성 편집기는 단독으로 읽히지 않아도 부모 창에서 보일 수 있습니다. 실제로 확인한 부모 창이 있다면 --parent-hwnd로 함께 지정합니다. 별도 검색 창이나 업무 창은 --related-hwnd로 명시할 수 있습니다.

python -X utf8 -B .\scripts\observe.py observe --exe-name "APP.exe" --pid 1234 --hwnd 5678 --stage combo --parent-hwnd 9012 --output "$outputDir"

여기도 모든 숫자는 현재 inventory.json과 실제 창에서 확인한 값으로 바꿉니다. 부모/관련 창은 같은 PID여야 하며, 같은 PID라는 이유만으로 업무 관계를 추정하지 않습니다.

결과는 target-window.json, parent-window.json 등으로 따로 남습니다. 목록에 없는 팝업은 미관찰로 남기며, PID 전체의 다른 업무 창을 훑어 메뉴를 찾는 기능은 사용하지 않습니다. 부모 창에서도 보이지 않으면 기존 별도 접근성 진단과 비교할 수 있지만 자동 클릭으로 해결하지 않습니다.

9

확인된 범위와 보관 원칙

이번 패키지는 자체 WinForms/WPF 합성 화면 6개 상태에서 관찰과 데이터 경계를 검증했습니다. 실제 회사 FX/FxMenuAgent는 다른 PC에 있어 현장 인식률과 DPI별 동작은 아직 검증하지 않았습니다. 숨겨진 UI 요소를 복원하거나 실제 Infragistics/FarPoint의 모든 동작을 보장하는 결과는 아닙니다.

  • 관찰 래퍼는 JEV, 외부 모델 호출, 자동 다운로드, 업데이트 확인과 원격 로그 전송을 실행하지 않습니다.
  • 원시 결과는 승인된 사내 모델 환경에서만 읽고, 외부 대화나 공개 이슈에 첨부하지 않습니다.
  • 이 도구가 호스트 모델의 전송 정책이나 폴더 동기화를 통제하지는 못합니다. OS 네트워크 차단을 보장하는 샌드박스도 아닙니다.
  • 원본 EXE에는 이 래퍼 이외의 기능도 있으므로 scripts/observe.py를 통해 사용합니다. 원본 EXE를 직접 실행하는 방식으로 제한을 우회하지 않습니다.
  • Windows의 사용자별 interaction lock 같은 흔적이 결과 폴더 밖에 생길 수 있습니다. 기존 CUA 설정, UAC, 백신과 방화벽은 변경하지 않습니다.
원본 바이너리는 Authenticode 서명이 없습니다. 회사 정책이 실행을 차단하면 중단하고 담당자에게 실행 가능 여부를 확인하세요. “차단 해제”나 관리자 권한 실행을 이 안내의 필수 단계로 요구하지 않습니다.
