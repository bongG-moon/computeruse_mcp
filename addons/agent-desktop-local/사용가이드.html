사용 안내 | Agent Desktop Local 0.2.0

Claude Code에서
업무 화면을 읽고 실행하기

“MES Setup을 N으로 바꾸고 확인해 줘”처럼 요청하면, 사내 모델이 현재 화면을 읽고 로컬 엔진으로 조작한 뒤 결과를 다시 확인합니다. 0.2.0부터 실행 기능을 추가했으며 기존 읽기 전용 관찰도 그대로 사용할 수 있습니다.

Windows x64관찰 + 조작사내 모델별도 CUA Driver 불필요
어떤 파일을 받나요?
windows-x64.zip

실행 엔진과 스킬, 이 가이드가 들어 있습니다. source.zip은 개발용입니다.

실행 엔진이 있나요?
EXE가 포함됩니다

bin/agent-desktop.exe가 읽기와 조작을 수행합니다. CUA Driver는 필요 없습니다.

따로 준비할 것은?
Python 3.10 이상

회사에서 승인한 Python과 로컬 파일/명령 도구가 있는 Claude Code를 사용합니다.

1

0.2.0 Windows ZIP을 새 폴더에 풉니다

computeruse_mcp의 별도 릴리스에서 Agent-Desktop-Local-0.2.0-windows-x64.zip을 받습니다. ZIP을 오른쪽 클릭해 모두 압축 풀기를 선택하세요.

회사에서 허용한, 본인이 쓸 수 있는 동기화되지 않는 로컬 디스크 폴더를 고릅니다. 기존 CUA 폴더나 개인 Claude 설정을 덮어쓰지 않습니다. ZIP 안에서 바로 실행하거나 EXE만 따로 옮기지 마세요.

agent-desktop-local
├─ SKILL.md
├─ 사용가이드.html
├─ bin
│  └─ agent-desktop.exe
├─ scripts
│  ├─ observe.py          ← 읽기 전용
│  └─ interact.py         ← 관찰 후 조작
└─ references
   └─ actions.md
이 스킬은 기존 CUA v0.19.5와 별도 배포입니다. 예전 CUA ZIP을 다시 받거나 CUA Driver를 추가해도 0.1.x 스킬에 조작 기능이 생기지는 않습니다. 0.2.0의 폴더 전체를 사용하세요.

원본 엔진은 agent-desktop 1.1.0 그대로입니다. JEV, npm, 별도 MCP 서버, 커널 드라이버와 상시 서비스는 설치하지 않습니다. Python은 이 ZIP에 포함되어 있지 않습니다.

2

Claude Code에서 스킬을 읽게 합니다

먼저 회사에서 승인한 내부 모델을 사용하는 Claude Code를 엽니다. 모델 주소나 인증, 기존 도구 권한을 이 스킬 때문에 바꿀 필요는 없습니다.

가장 간단한 방법: SKILL.md의 전체 경로를 알려 주기

탐색기에서 SKILL.md를 Shift + 오른쪽 클릭 → 경로로 복사한 뒤 Claude Code에 아래처럼 요청합니다. 경로는 실제 위치로 바꾸세요.

아래 경로의 Agent Desktop Local 0.2.0 SKILL.md를 읽고 따라 줘.
D:\LocalTools\agent-desktop-local\SKILL.md

내가 열어 둔 업무 창의 MES Setup 콤보를 N으로 변경하고, 현재 선택값을 다시 읽어서 확인해 줘. 같은 이름의 창이나 항목이 있으면 현재 트리로 구분해 줘. 저장은 이번 요청에 포함하지 않을게. 결과는 이 스킬 폴더 아래 results에 보관하고 사내 모델 환경 안에서 해석해 줘.

저장까지 원하면 요청에 포함하면 됩니다. 이 예시의 “저장 제외”는 제품의 고정 제한이 아닙니다. 이미 요청한 조작마다 다시 승인을 묻도록 만들지 않았으며, Claude Code 자체의 기존 도구 승인 방식은 유지됩니다.

계속 사용할 프로젝트에 등록하기

  1. Claude Code에서 사용할 프로젝트 폴더에 .claude\skills 폴더를 만듭니다.
  2. 압축을 푼 agent-desktop-local 폴더 전체를 그 안에 복사합니다.
  3. 아래 구조인지 확인하고 새 대화에서 /agent-desktop-local을 호출합니다.
내 프로젝트
└─ .claude
   └─ skills
      └─ agent-desktop-local
         ├─ SKILL.md
         ├─ bin
         ├─ scripts
         └─ references

프로젝트 스킬 위치와 슬래시 호출은 Claude Code 공식 스킬 문서에 따른 방식입니다. 개인 전체에 설치하는 대신 필요한 프로젝트만 선택하면 됩니다. 이 가이드가 파일을 자동 복사하거나 개인 설정을 수정하지는 않습니다.

계속 “읽기 전용이라 실행할 수 없다”고 답하면, 실제 읽은 SKILL.md 경로와 첫 제목의 버전을 확인해 달라고 요청하세요. 0.1.x 스킬이나 이전 대화의 지침을 사용 중일 수 있습니다. 같은 이름의 개인 스킬을 자동 삭제하지 말고, 새 대화에서 0.2.0 파일의 전체 경로를 명시하세요.

채팅 전용 모델만 연결한 대화창에서는 실행되지 않습니다. Claude Code에 로컬 파일 읽기와 명령 실행 도구가 있어야 합니다. 도구가 허용되지 않은 상태라면 기존 회사 권한 절차를 따릅니다.

3

작업을 요청하면 이렇게 진행됩니다

대상 확인실행파일과 업무 창
현재 화면 읽기컨트롤과 ref 확인
한 번 실행요청한 클릭/값 변경
다시 확인새 화면의 값과 상태

사용자는 FX를 평소처럼 열고 대상 업무 화면을 준비합니다. Claude Code가 실행파일 이름과 창 목록을 확인하고, 현재 화면에서 라벨과 콤보, 표와 편집기를 구분합니다. 화면이나 컨트롤이 여러 개면 임의로 하나를 선택하지 않습니다.

요청 예시스킬이 수행할 일
“현재 콤보 값만 읽어 줘”observe.py로 읽기 전용 확인. 입력 없음
“MES Setup을 N으로 바꿔 줘”현재 콤보를 식별하고 선택/값 변경 후 다시 읽기
“조회하고 이번 결과를 확인해 줘”요청 범위의 버튼을 실행하고, 이번 조회 완료 근거 확인
“이 표를 내보내고 파일을 확인해 줘”현재 메뉴와 범위를 확인해 실행하고, 실제 파일 생성 결과 별도 확인

일부 컨트롤은 접근성 API로 조작되지 않을 수 있습니다. 물리 입력과 포커스 이동이 필요한 지원 명령은 --headed를 명시해 실행합니다. 이때는 에이전트가 조작하는 동안 같은 PC에서 마우스와 키보드를 사용하지 마세요.

클릭 전달과 업무 완료는 다릅니다. 콤보가 N으로 읽혔다고 데이터베이스 저장까지 완료된 것은 아닙니다. 메뉴가 닫혔다고 Excel 파일이 생성된 것도 아닙니다. 확인된 결과와 확인하지 못한 결과를 나누어 보고합니다.
4

Python과 로컬 결과 폴더를 준비합니다

Claude Code가 실행해도 되며, 직접 확인하려면 탐색기에서 SKILL.md가 보이는 폴더의 주소 표시줄에 powershell을 입력하고 Enter를 누릅니다. 관리자 PowerShell을 열 필요는 없습니다.

python --version

Python 3.10 이상이면 사용할 수 있습니다. Windows는 10 1809 이상 x64 환경이 필요합니다. Python을 찾지 못하거나 설치 화면이 뜨면 자동 설치를 진행하지 말고 회사에서 승인한 기존 Python 경로를 사용하세요.

Python 전체 경로를 사용하는 예시
& "D:\ApprovedPython\python.exe" --version

공백이 있는 경로는 따옴표로 감싸고 앞에 &를 붙입니다. 이후 명령의 첫 python도 같은 방식으로 바꿉니다. 예시 경로를 그대로 사용하지 마세요.

아래 두 줄은 스킬 폴더 안에 results를 만들고 절대 경로를 변수에 넣습니다.

New-Item -ItemType Directory -Force .\results | Out-Null
$outputDir = (Resolve-Path .\results).Path
결과 폴더 전체에 업무 텍스트와 조작 값이 남습니다. OneDrive, 클라우드 동기화 폴더와 공유 드라이브를 사용하지 마세요. 이 도구는 네트워크 경로를 거부하지만 로컬 폴더의 동기화 여부까지 판별하지 못합니다.
5

명령으로 실행하는 방법

보통은 2번의 자연어 요청으로 충분합니다. 아래는 Claude Code가 사용하는 명령을 이해하거나 수동 점검할 때 참고하세요. 실행 위치는 SKILL.md가 있는 폴더입니다.

① 현재 업무 창 확인

작업 관리자 → 세부 정보에서 정확한 실행파일 이름을 확인합니다. 아래 APP.exe를 실제 이름으로 바꿉니다.

python -X utf8 -B .\scripts\observe.py inventory --exe-name "APP.exe" --output "$outputDir"

출력된 receipt는 results 아래 새 폴더 이름입니다. 그 폴더의 inventory.json을 사내 환경에서 읽어 title, pid, hwnd를 확인합니다. 같은 PID 안에도 서로 다른 업무 창이 있을 수 있습니다.

② 조작 직전 화면 읽기

아래 숫자 1234, 5678은 예시입니다. 현재 확인한 PID와 HWND로 바꿉니다.

python -X utf8 -B .\scripts\interact.py inspect --exe-name "APP.exe" --pid 1234 --hwnd 5678 --output "$outputDir"

새 receipt 폴더의 inspection.json과 before.json에서 조작할 컨트롤의 역할, 조상 경로, 현재 값과 ref를 확인합니다. 이 폴더가 한 번 조작할 수 있는 세션입니다.

③ 해당 ref로 한 번 실행

아래 세션 ID와 ref도 예시입니다. 방금 만든 실제 값으로 바꿉니다. 현재 관찰에서 값 쓰기를 지원하는 것으로 확인된 콤보를 N으로 바꾸는 예시입니다.

$sessionDir = Join-Path $outputDir "0123456789abcdef0123456789abcdef"
python -X utf8 -B .\scripts\interact.py act --session "$sessionDir" --ref "@s8f3k2p9:e12" --action set-value --value "N"

콤보라는 이유로 항상 select를 사용하는 것은 아닙니다. Claude Code는 현재 available_actions와 Provider 근거에 맞춰 set-value 또는 select 등을 선택합니다. type은 삽입 위치에 입력하므로 전체 교체와 다릅니다. 지원 명령 전체와 headed 조건은 references/actions.md에 있습니다.

세션은 120초 안에 한 번 사용합니다. 다음 조작은 새 inspect부터 시작하세요. 실패나 타임아웃 후 같은 입력을 반복하지 말고 현재 결과부터 읽습니다. Ctrl+C로 중단했어도 이미 전달된 동작은 취소되지 않을 수 있습니다.

④ 새 관찰로 결과 확인

같은 세션 폴더의 action.json, after.json, verification.json을 확인합니다. 실제 선택값, 체크 상태, 텍스트 또는 업무 결과가 요청과 일치하는지 판단하세요. 오류나 중단 시 일부 파일은 없을 수 있으며, 없는 결과를 성공으로 추정하지 않습니다.

트리가 값을 생략한 경우, 새 ref에서 별도로 읽은 값이 after-value.json에 남을 수 있습니다. 빈 문자열과 값이 관찰되지 않은 상태는 다릅니다.

관찰 준비 요약은 inspection-receipt.json, 엔진 응답 직후 요약은 dispatch-receipt.json, 사후 관찰까지의 최종 요약은 action-receipt.json입니다. 세션 안의 실행 흔적을 삭제하거나 수정해 같은 입력을 다시 보내지 마세요.

6

읽기 전용 비교도 계속 사용할 수 있습니다

조작하지 않고 현재 값을 읽거나 기존 CUA와 비교하려면 이전과 같이 observe.py를 사용합니다. 아래 이름과 숫자는 실제 대상으로 바꿉니다.

python -X utf8 -B .\scripts\observe.py observe --exe-name "APP.exe" --pid 1234 --hwnd 5678 --stage combo --output "$outputDir"

--stage는 window, menu, combo, grid, property 중 하나입니다. 해석의 종류만 지정하며 이 관찰 명령 자체는 클릭하거나 펼치지 않습니다.

팝업이 단독으로 읽히지 않으면 실제로 확인한 부모 HWND를 --parent-hwnd로 함께 읽을 수 있습니다. 별도 관련 창은 --related-hwnd로 명시합니다. 같은 PID여야 하지만, 같은 PID라는 이유만으로 업무 관계를 추정하지 않습니다.

수동 관찰 중 PowerShell로 돌아오면 콤보가 닫히는 경우

아래처럼 8초 대기 후 관찰하도록 준비하고, 그 사이 FX로 돌아가 원하는 메뉴나 콤보를 직접 엽니다. 관찰 중 다른 창으로 전환하지 않습니다.

Start-Sleep -Seconds 8
python -X utf8 -B .\scripts\observe.py observe --exe-name "APP.exe" --pid 1234 --hwnd 5678 --stage combo --output "$outputDir"

관찰이 끝난 뒤 결과를 확인하세요. 전경 변경으로 interrupted가 나오면 유효한 관찰로 취급하지 않습니다.

관찰 폴더에는 target-window.json, observation.json, receipt.json 등이 남습니다. observed는 트리를 읽었다는 뜻이며 업무 인식이나 완료를 보장하지 않습니다. 빈 트리와 미노출 값은 추정해 채우지 않습니다.

7

실행 결과를 이렇게 해석하세요

화면에 출력되는 짧은 JSON은 요약입니다. 업무 내용과 조작 전후 근거는 로컬 세션 폴더에서 확인합니다.

ready는 조작용 관찰이 준비됐다는 뜻입니다. completed는 새 관찰에서 컨트롤의 값이나 상태가 맞았다는 뜻이며 업무 저장 성공은 아닙니다. executed_unverified는 실행 후 결과 미확인, verification_failed는 읽힌 상태가 기대와 다름을 나타냅니다.

delivery뜻과 다음 행동
not_delivered엔진이 입력을 전달하지 않았다고 보고했습니다. 현재 대상과 원인부터 다시 확인합니다.
delivered_verified엔진이 해당 요소의 결과를 확인했습니다. 요청한 업무 결과는 새 관찰로 별도 확인합니다.
delivered_unverified전달됐으나 결과가 충분히 확인되지 않았습니다. 재입력하지 않고 현재 상태를 읽습니다.
possibly_dispatched전달 여부가 불확실합니다. 타임아웃이나 중단 직후 입력이 이미 적용됐을 수 있으므로 반복하지 않습니다.

input_dispatched: false는 입력 미전달, true는 전달됨, null은 전달 여부 미확인을 나타냅니다. null을 false처럼 취급하지 마세요. 조작 뒤 화면을 읽지 못했다면 “실행 후 결과 미확인”으로 보고해야 합니다.

흔한 문제

  • 읽기 전용이라고 거절: 새 대화에서 0.2.0 SKILL.md 전체 경로를 명시하고, 조작 요청은 interact.py 경로라고 확인합니다.
  • 일치하는 창이 없음: 앱 실행 상태, 정확한 EXE 이름, 현재 PID와 HWND를 다시 확인합니다.
  • session/ref 만료 또는 이미 사용됨: 새 inspect를 만듭니다. 이전 조작이 전달됐는지 먼저 읽고 재입력 여부를 판단합니다.
  • 대상 동작 미지원: 현재 Provider가 조작 경로를 제공하는지 확인합니다. 라벨을 클릭하거나 임의 좌표로 우회하지 않습니다.
  • 보안 정책이 EXE 실행을 차단: 정책을 낮추거나 관리자 권한으로 우회하지 않습니다. 회사에서 실행할 수 있는지 확인합니다.

데이터 보관과 실제 FX 검증 범위

이 패키지의 검증 결과는 VALIDATION.md에 기록합니다. 실제 회사 FX/FxMenuAgent는 다른 PC에 있어 현장 인식률, 실제 저장 결과와 DPI별 동작은 아직 검증하지 않았습니다. 합성 화면 테스트가 실제 Infragistics/FarPoint의 모든 동작을 보장하지는 않습니다.

  • 래퍼는 JEV, 외부 모델 호출, 자동 다운로드, 업데이트 확인과 원격 로그 전송을 실행하지 않습니다.
  • 원시 트리와 조작 값은 로컬 파일에 남습니다. 결과 폴더 전체를 업무 자료로 취급하고 승인된 사내 모델 환경에서만 읽습니다.
  • 이 도구가 Claude Code 호스트의 전송 정책이나 폴더 동기화를 통제하는 것은 아닙니다. OS 네트워크 차단을 보장하는 샌드박스도 아닙니다.
  • 원본 EXE의 다른 명령으로 래퍼를 우회하지 않습니다. 화면 캡처, 클립보드 명령과 임의 좌표 입력은 이 스킬의 조작 경로에 없습니다.
  • Windows의 사용자별 interaction lock 같은 흔적이 결과 폴더 밖에 생길 수 있습니다. 기존 CUA, UAC, 백신과 방화벽 설정은 변경하지 않습니다.
원본 EXE는 Authenticode 서명이 없습니다. 회사 정책이 차단하면 중단합니다. “차단 해제”나 관리자 권한 실행은 이 가이드의 설치 단계가 아닙니다.
